# 0102. Demo seats: a seat manager, Caddy routing by cookie, and updates only when seats are empty

- **Status:** Accepted, amended by 0103 (where `oj-demo` is installed; the demo user's firewall)
- **Date:** 2026-10-22

## Context
The public demo at demo.optionsjourney.com (decision 0100) runs the real app, which keeps one account, one clock and one tour per process. Visitors must not see each other's trades, and a visitor who leaves must not leave a used account for the next one. Decision 0101 put the demo on the always-on prod Mac, under its own macOS user, as LaunchDaemons at low CPU priority, with a 10-seat cap. The demo design spec's Railway hosting is replaced by 0101 and this decision.

## Decision
- **One process per visitor ("seat"), and a seat manager in front.** The manager (`demo/manager.py`, on `127.0.0.1:8096`, not in demo mode itself) keeps up to 10 seats, each a full demo app (`python -m optionsjourney` with `BROKER_CREDENTIALS=demo`) on its own port (5101–5110) and its own empty data folder. It keeps one or two seats warm, hands a ready seat to each new visitor, queues visitors when all ten are taken, and resets a seat after 20 minutes without activity or 60 minutes in all. The pool's decisions are pure logic (`demo/seats.py`); starting, checking and stopping processes is `demo/seat_process.py`.
- **Caddy routes by cookie.** The manager seats a visitor by setting `oj_seat=<n>.<token>` (Secure, HttpOnly, SameSite=Lax). Caddy (`packaging/demo/Caddyfile`, on `127.0.0.1:8095`, behind the tunnel) sends a request whose cookie starts `oj_seat=<n>.` straight to seat n, WebSockets included; it reads only the number. `/_seat/*` and `/stats` always go to the manager, and so does anything without a seat cookie. A seat that doesn't answer (502/503) sends its visitor to `/_seat/ended`.
- **The seat checks the token itself.** Each start of a seat gets a fresh random token (`DEMO_SEAT_TOKEN`). A seat lets in only requests whose cookie carries that token (Socket.IO too) and sends anything else to `/_seat/ended`. So an old cookie, a guessed seat number or a cookie from before a reset gets nowhere, even though Caddy routes on the number alone.
- **Cookies:** `oj_seat` (the seat) and `oj_wait` (a place in the queue, so a reload keeps it). Both are session cookies set by the demo's own pages; there are no other cookies and no third-party scripts.
- **Counts, with no personal data.** The manager keeps daily counts in a small JSON file: visits, how many waited and for how long, time spent, and the furthest tour step reached. No IP addresses, names, user agents or fingerprints. The author reads them at `/stats` behind a password (`DEMO_STATS_PASSWORD`; without one, `/stats` is a 404). 90 days are kept.
- **Hosting is one command:** `oj-demo install | start | stop | restart | status | update | logs` (`packaging/demo/oj-demo`) and a menu bar item, as for the site. Three LaunchDaemons, all running as the `ojdemo` user from its own checkout of the public repo: the manager (`Nice 10`, restarted if it stops, 30 seconds to stop its seats), Caddy, and an update job every 5 minutes (`Nice 10`, low-priority disk). `stop` disables them, so the demo stays stopped through a reboot.
- **Updates wait for empty seats.** The update job fetches the public repo's `main`. When it moved, it updates (checkout, `uv sync --frozen --no-dev`, restart the manager) only once no visitor is seated, or after 30 minutes from when the new commit was first seen. A failed `uv sync` goes back to the last commit and isn't retried until main moves again.
- **The stats password is kept in the manager's LaunchDaemon plist**, which `install` writes as root-owned and readable only by root (600). launchd can't read a value from another file, and the manager takes it only from its environment. An admin of the Mac can read it, and so can the `ojdemo` user from its own process's environment; it guards visitor counts only.
- **Root never trusts what `ojdemo` can write.** `ojdemo` faces the internet, so nothing that runs as root (`install`, `start`, `stop`, `restart`, `status`, `logs`) executes, sources or reads anything `ojdemo` can write (its home, checkout, `.git`, venv, uv cache, state and logs), and nothing installed for the admin comes from there. Lookups in those places (the live commit, a waiting update, the logs) run as `ojdemo` and their output is treated as text. Root's PATH holds system folders only. The LaunchDaemons' logs are in `/Library/Logs/optionsjourney-demo/`, a root-owned folder holding log files `ojdemo` owns. `install` runs from the admin's own clone of the public repo and refuses `ojdemo`'s files. It copies `oj-demo` to `/usr/local/bin` as root-owned, and copies the menu bar item the same way. A sudoers rule (checked with `visudo -c` first) lets the admin run `start`, `stop`, `restart` and `status` without a password, for the menu bar.

## Why
- A process per visitor reuses the whole app unchanged. Making the app serve many accounts at once would touch every service, the clock and the tour, all for the demo.
- Routing in Caddy keeps the manager out of the path of every request and WebSocket frame; the manager only seats people. A token checked in the seat means Caddy's routing doesn't have to be secret.
- Waiting for empty seats means an update never ends someone's visit in the middle, while the 30-minute limit keeps a busy demo from never updating.
- Turned down: one shared demo for everyone (visitors would trade on each other's account); Docker containers per visitor (more moving parts on a Mac that also trades); a manager that proxies every request itself (another hop for every quote push).

## Consequences
- Ten seats use about ten app processes' worth of memory when the demo is full; Nice 10 keeps the trading app ahead on CPU.
- A restart of the manager (an update, `oj-demo restart`) ends every visit; visitors land on "This demo session has ended" with a button to start again.
- Changes to `oj-demo` itself, the menu bar item or the LaunchDaemons need the admin to pull their own clone and run its `oj-demo install` again; the update job logs when `oj-demo` changed on main.
- Before the demo goes live, the trading account's home folder must be closed to other users and `ojdemo` checked for access to it (0101), and the tunnel gains `demo.optionsjourney.com` → `http://127.0.0.1:8095`.
