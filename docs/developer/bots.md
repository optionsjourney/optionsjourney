- **`settings._preopen_checked`:** the New York date the 09:20 pre-open check last ran (slice 14).
- **`settings._leave_paused`:** the pause for "left open" (`bot_store.LEAVE_PAUSE_KEY`): `on` (until resumed), an ISO time (until then) or `off`/no row. An unreadable or malformed value counts as paused, so a wing is sold, never left unwatched.
- **`bot_entry_times`:** `time`, `enabled`, and from 0016 `quantity` (nullable: that time's contracts) and `label`.
- **`bot_chase`:** per bot and `phase` (`entry`, `exit`): `start_offset`, `step`, `interval_seconds`, `max_tries`, and from **0018** `exhaust_mode` (`give_up`, `natural_then_leg_out` or `keep_conceding`; the migration's default `give_up` keeps existing bots' closes as they were) and `natural_minutes` (default 2), and from **0039** `ignore_bidless_longs` (Boolean, server default false; decision 0065, #157). Only the exit row's are read, and an entry chase with `ignore_bidless_longs` on fails validation (`chase_exhaust`). The form's `chase-exit-bidless` box sets it (exit phase only); the close that uses it is described under the target close. A bot with no exit row at all loads the exit defaults with `give_up` (never a leg-out it wasn't saved with).
- **`bot_runs`:** one per entry attempt. `key` is unique (`bot-{id}-{HHMM}-{YYYYMMDD}`; a manual preview uses `bot-{id}-now-{timestamp}`) and is the claim. Also `status`, `live` (at fire time), `account_number` (the bot's account at the claim; the run's exits trade there even if the bot is edited), `reason`, `legs` (JSON, the picked strikes), `target_credit`, `fill_credit`, `filled_legs`, `broker_order_id`, `contracts` (units filled), `chase_log`, `filled_at`. A later tranche of an entry is its own row: `parent_run_id` is the root run, and its `key` is `<root key>#t<N>`.
- **`bot_exits`:** per run and side: `kind` (`stop`, `target`, `wing`, `timed`, `action`, `close`), `state` (`placing`, `pending`, `armed`, `working`, `firing`, `chasing`, `filled`, `cancelled`, `failed`, `expired`, `left`, `missed`, `reduced`; `placing` = written but not sent yet, `pending` = a stop held back by Freeze, `firing` = a target or timed close whose close is running, `chasing` = a wing being chased in the background, `missed` = a timed close the session ended without; a `timed` row `expired` found nothing held), `cancel_requested_at` (0018: Cancel pressed on a running close), the short and long symbols, `contracts`, `broker_order_id`, `trigger`, `limit`, `fill_price`, `rearms`, `rearm_day`, and a `log` of the arithmetic and each step. Exits store their own symbols, so they work whether the journal shows the trade split or combined.
- **`order_log.bot_run_id`:** nullable, SET NULL. It ties each order attempt to its run.
- **Positions are links, not rows.** Nothing is copied into the journal's data: the journal finds a bot's trades by their opening order id (see "The journal link").

Orders a bot tried are in `order_log` ([orders.md](orders.md)).

## Services
### `bot_store.py`
Reads and writes a definition from the tables (`load`, `listing`, `armed`, `save`, `parse_form`), the run and exit queries the pages use, and `set_armed` / `set_live` / `hide`. **`skip_day`** (Tracker2's `api_skip_day`) adds the next entry day to `blackout_days` for an armed bot only (it returns `None` otherwise); with the toggle off it first drops the old dates, so dormant ones don't come into force, and it prunes past dates. **`undo_skip`** removes the date and turns the toggle off when none are left. **`skip_many`** does `skip_day` for several bots and returns (skipped, refused). Skip a day also clears ticked blackout lists when blackout days was off (Tracker2's `_add_blackout_day`), and Undo leaves blackout days on while lists remain. `grouped_runs` orders the runs page: each root newest first, then its tranches as (run, 2), (run, 3). `parse_form` reads the new fields (blank caps are `None`). `read_form` returns the same `BotDef` plus the problems it can't hold: an entry-time quantity that is present but unreadable or 0 (`times`), or a premium bound that is present but unreadable (`premium`), each naming the text typed, since as a `BotDef` they'd read as blank and pass. The save route passes them to `save(..., form_problems)`, which merges them over validation's problems. `save` validates first and writes the legs, sides, times and chase rows fresh each time; a new bot (typed, cloned or imported) is always created `live=True, enabled=False` (decision 0061). Saving an existing bot switches it off and sets it to Paper (`live=False, enabled=False`) when its broker changes (slice 11) or when the change makes `definition.app_watched` true where it was false (final review I3: a group's stop is now watched by the app), so it's armed and made live again through the "watched by the app" box; the save route flashes why. `hide` disarms and hides a bot so the journal keeps its link. Slice 8: `listing(archived=False)` (hidden bots never; archived ones only with `archived=True`), `armed` (never an archived bot), `archived_count`; `set_armed` returns False and changes nothing when asked to arm an archived bot; `save` writes the normalised tags, never `archived_at`, and takes `imported_at` for a new bot. **`clone`** (Tracker2's `api_clone_bot`): the loaded definition saved as a new bot named by `copy_name` (" (copy)", " (copy 2)" …, any "(copy N)" stripped first, every bot's name counted), through `save`, so it's validated, off, and in its source's mode (Live or Paper); a bot that fails validation returns its problems and no copy. **`open_trade_reasons`** (`archive.open_trade_reasons`): runs holding an open side (`caps.open_runs`), exits in `LIVE_EXITS` (`placing`, `pending`, `working`, `armed`, `firing`, `chasing`) unless every leg of the row (`exit_math.row_legs`) is past expiry, and runs `running` or `pending`, each as "N open trade(s) (run …)", "N exit(s) still working (run …)", "N entr(y/ies) in progress (run …)". **`archive`** refuses with those, else disarms and sets `archived_at`; **`unarchive`** clears it, still disarmed. **`imported_name`** (`_imported_name`): the name, or " (imported)", " (imported 2)" … when taken. **`import_bot`** saves the file's bot with the importer's choices as a new bot (`id=None`), validated, off, Live like any new bot, `imported_at` = the file's `exported_at` (or now). Its `source_url` (decision 0056) is stored as `imported_from_url`; `save` takes it as `imported_from_url` for a new bot only. `imported(bot_id)` (the `exported_at` and the link, `(None, None)` for a bot not imported).

### `bot_fetch.py`
`fetch(url, http=None, resolve=…)` (decision 0056, #137; Tracker2's `share_import.fetch_snapshot`): the text of the bot file a link gives, for `bot_file.parse`. `bot_link.direct` first; then each step by hand (`follow_redirects=False`, at most `MAX_REDIRECTS` 5), every redirect's `Location` through `bot_link.check` and every host's addresses (`socket.getaddrinfo`) through `bot_link.is_public`, so neither a redirect nor a name can lead to this computer or the home network. `TIMEOUT_S` 10, a browser-like `User-Agent`. Reads at most `bot_file.MAX_BYTES` + 1; UTF-8 with a byte-order mark dropped. Every failure is a `FileError` for the user: 401/403 (not shared publicly), any other non-200, too large, not text, a web page (starts with `<`: a sign-in or a share page), a timeout, unreachable, a name that can't be found, too many redirects. The trading guard passes it (a GET to another host).

### `bot_entry.py`
`fire(deps, bot_id, hhmm, manual=False)` is Tracker2's `orchestrator.run_bot_entry`.
1. **Claim:** insert the `bot_runs` row first. A unique-key conflict (`IntegrityError`) means it already fired and `fire` returns `None`. The run id goes into `ACTIVE` from the claim until the run is fully settled, so recovery leaves it alone.
2. **Guards** (`_guard`), each a `skipped` run with a reason: an **archived** bot first (slice 8; Preview order too: "The bot is archived. Unarchive it first."), Freeze, No new trades (not for a manual preview), not armed (not for a manual preview), not TastyTrade, the market not in its regular session, inside the entry cut-off, then the bot's own guards, none of which apply to a manual preview: **blackout day** (the first of them, `_blackout`: a typed day, or a ticked list whose answer is True, "today is a blackout day (FOMC)", or with a Before expiration list's day ahead, "today is a blackout day (FOMC on 2026-10-15, before expiration)"; it looks up the window only for a bot with a Before expiration list and a DTE above 0); a ticked list that **can't tell** (today, or a day in the window) skips the entry, "FOMC dates unavailable today, so the blackout can't be checked.", failing closed), the daily contract limit (`orders.used_today` plus this entry's contracts), then `_bot_limits`: **max entries per day** (`_entries_today`: distinct `coalesce(parent_run_id, id)` among today's `filled`, `partial`, `running`, `preview` and `pending` runs other than this one (`COUNTED`; `pending` is a scheduled run still in progress, which a Paper run stays until its pretend fill is recorded, so two overlapping entries can't both pass), leaving out Preview order runs by their `-now-` key, so a root and its tranches are one entry) and **max open trades** (`_open_trades`, below; if counting raises, the entry is skipped with "Couldn't count this bot's open trades; not entered.", so it fails closed), and last the **market filters** (`_market_filters` → `bot_filters.check`, the only guards that go over the network). A filter that couldn't be checked skips the run and alerts once per bot, filter and New York day (`bot_filters.first_today`), "IC: entry skipped, VIX level unavailable"; an ordinary miss is on the run only. A day outside the bot's frequency never gets here: the clock creates no run for it. `used_today` counts **opening** sends only, so the bot's own stops, re-arms and closes never use up its limit; see "Counting against the daily limit" below. The contracts come from `contracts_for`; a clamp is written first in the run's `chase_log` as `{"capped": asked, "to": sent}`.
3. **Expiration and chain:** each leg's DTE resolved to one of the underlying's listed expirations (never today plus dte; slice 14, `bots/expirations.py`), then the chain's rows for each and the spot price. No chain or price is an `error`.
4. **Strikes and price** from `bots/strikes.py`; the run records `legs` and `target_credit`. Slice 10 (`_pick`): a bot with `market_picks` is refused with `NoData` ("SPX's price is stale") when the hub's quote for the underlying is more than `SPOT_FRESH` (30 s) old by `last_at` or `at` (no hub quote: the analyzer's price, as before); a bot with a delta leg builds its chain with deltas (`expires_at` = today's 16:00 close). A `NoData` skip alerts once per bot, kind (`deltas`, `SPX price`) and New York day (`_no_data`, `bot_filters.first_today`). Each leg with a delta records it as text (`legs[].delta`, 4 places). **Requote (#205, Tracker2's `entry_requote`):** a live entry (`_fire` with `live`; not Paper, Preview order or futures) re-reads its picked legs right after `_find_legs`, before `enter_picked` checks the side, premium bounds, sizing and the chase: `fresh_option_quotes(clients, symbols)` asks TastyTrade's REST `market_data({"equity-option": ...})`, then Schwab's `quotes` for any symbol without both a bid and an ask (decision 0080's order; never the stream or the chain; a failing broker is logged and skipped). `strikes.requote(picked, quotes)` (pure) replaces each leg's `mid` only when **every** leg has a sane two-sided quote (bid ≥ 0, ask > 0, bid ≤ ask), keeping strikes and deltas; otherwise, or on any exception, the chain's prices stand, so a quote outage never blocks an entry. Each changed leg adds a note ("leg 3 requoted at entry: 2.95 x 3.15, mid 3.05 (the chain had 2.50)") to the run log's `strikes` entry. For a scheduled entry, `filters.premium_problem` checks the net premium (the signed sum of mids, before the start offset) and a miss is a `skipped` run with its reason. A first price below `MIN_CREDIT` ($0.05, or a debit) is a `skipped` run ("The credit is below $0.05; not entered."), before anything is sent.
5. **Order:** one opening limit order with every leg at its ratio through `orders.submit` (origin `bot`, with `bot_id` and `bot_run_id`). `preview_only` is set unless the bot is Live, so a Paper bot can never send. A scheduled Paper entry takes the one check as a preview and then goes to `_paper_entry`/`bot_paper.enter` instead of `_settle` (see Paper trading, below). The bot page's button is **Preview order** (below); `fire(manual=True)` remains for tests and the old preview runs.
6. **Chase** via `bot_chase.chase_entry` (below), then `_settle` writes the outcome. Every filled run's exits are placed **after the chase ends** (Tracker2's orchestrator), not the moment a tranche fills; `record_fill` has already frozen `fill_credit`, `filled_legs`, `contracts` and `filled_at` for each one, at once. Then each run left without a fill is ended by `_end_run`: `preview`; `refused` (an `error` run with an alert); `unclear` (stays `running` for recovery, with an alert); `uneven` (see below); `missed` (alert). If the root filled nothing but a later tranche did, the root is `missed`. A `short` ending (some filled, tries ran out) alerts "Entry short: N of M filled — rest given up".

**Tranches.** `_tranche_run` makes the child run: `key = <root key>#t<N>`, `parent_run_id` the root, status `running`, contracts = the rest, the root's legs, target credit and account. The child is added to `ACTIVE` before it is committed. The chase log of the whole entry is on the root; each child gets its own part (`Entered.log_of`).

**Uneven legs.** `record_fill` records whole units only (`trading.orders.filled_units`, the smallest across the legs scaled by ratio) and alerts about leftover contracts, which the app doesn't track or protect. When the legs hold no whole unit, the run is left `running` with the reason `UNEVEN` ("Needs you: The entry's legs filled unevenly"), nothing more is sent, and `bot_loops._settle` skips any run whose reason starts with `UNEVEN`, so recovery never records or protects it. In recovery, a fill with no whole unit, or one with leftover legs, takes the same path.

Failures: an unexpected exception is logged and alerted. If an order may be out (status `running` or an order id), the run stays `running` for recovery; otherwise it becomes `error`. An exception after a fill keeps the fill and alerts ("exits not placed"; `hand_to_exits`, which recovery uses too, marks the run's reason "Needs you"). A read error or an unclear replace in the chase also leaves the run `running`. `alert(deps, title, detail, link)` and `update_run(deps, run_id, **values)` are public so the other bot modules use them. `BotDeps` carries the session factory, broker clients, quote hub, analyzer, `notify`, `sleep`, `now`, `background` and `market` (the filters' `bot_filters.Market`; `None` makes any filter that's on fail closed), all replaced in tests.

**The floating window** (slice 10; Tracker2's `orchestrator.run_bot_floating_entry`). `fire` is now claim + `_run` (ACTIVE, the catch-all); `_fire(..., miss=None)` sends every skip (guards, filters, no expiration, a non-`Unsafe` `NoTrade`, premium bounds, the credit floor) through `skip`, which with a `miss` calls it instead of writing a skipped run. **`fire_floating(deps, bot_id, hhmm)`**: outside the window → None; claim `floating.minute_key` (taken → None); another floating run today in `floating.STOPS` → the claim is deleted (`_drop`), None; else `_run` with `miss`, which deletes the claim, records `(day, minute, reason)` in `_floating_last` (`floating_last(bot_id, day)` for the bot page; per process) and, on the final minute when the bot has no floating run today, writes the `close_key` row `skipped` "Window 11:30–11:45 closed; last check 11:45: …". The contracts never come from an entry time's quantity (`contracts_for(bot, None)`). No chain or price is a miss for a window's minute (alerted once a day, `option chain`); a fixed entry's stays an `error`. A missed chase leaves its `missed` row and the next minute tries; an error (refused, `Unsafe`, an exception) ends the window. Before checking STOPS, `_settle_stuck_claims` ends as `skipped` any other floating claim still `pending`, not in ACTIVE, older than `STUCK_CLAIM` (2 minutes): nothing is sent while a claim is pending.

`services/chain._side_quote` adds the hub quote's `at` to TastyTrade rows (slice 10), for the delta freshness check.

### `bot_filters.py` and `market_feed.py` (the market filters)
- **`market_feed.read_dxlink(socket, token, want, wait_s, ready)`:** one short DXLink session (SETUP, AUTH, CHANNEL_REQUEST, FEED_SETUP, FEED_SUBSCRIPTION) for `Want(trades, summaries, candles)`. `Got` keeps each symbol's newest `Trade` (price, time), each `Summary` (`dayId`, `prevDayClosePrice`) and candle bars by time, keyed by `candle_key` (DXLink echoes `SPX{=1d}` back as `SPX{=d,…}`); a removal or price-less event is never a bar, and a history is complete on its snapshot's end flag. It returns as soon as `ready(got)` or at the deadline; an `ERROR` raises. **`TastyFeed`** opens it with TastyTrade's quote token (no TastyTrade client: `FeedUnavailable`). The live quote stream isn't touched. `Got.source` names the broker (`"TastyTrade"` by default).
- **Schwab fallback (#194):** **`SchwabFeed(clients, now)`** answers the same `Want` from Schwab's REST market data in one pass, never waiting, with `source="Schwab"`: trades from `quotes` (`quote.lastPrice`, `quote.tradeTime` ms); a summary pairing today's day id with the last `daily_closes` close before today, only when that close is `previous_session(today)` (an older one is left out); `{=1d}` candles from `price_history` with `periodType=year, frequencyType=daily` and `{=1m}` with `periodType=day, frequencyType=minute, needExtendedHoursData=false`, `startDate` = the `Want`'s from-time (2 minutes earlier for `{=1m}`, `MINUTE_HEADROOM_MS`, so a start Schwab takes as exclusive can't cost the 09:30 bar; earlier bars are ignored) and `endDate` = now. `candle_from_schwab` moves a daily bar (Schwab stamps New York midnight) to midnight UTC of its New York day, DXLink's convention; each history then gets a closing `SNAPSHOT_END`, so it's complete. Symbols go through `schwab_symbol` (`$` for `INDEXES` and VIX9D). No Schwab client, or a futures symbol (`/ES`), raises `FeedUnavailable`; a failed Schwab call raises its `BrokerError`. **`FallbackFeed(feeds)`** reads each feed in turn and returns the first `Got` for which `ready(got)` holds; a feed that raises is logged and skipped (`FeedUnavailable`, `BrokerError` and `CredentialsUnavailable` at info, anything else with its traceback); if none is ready it returns the last `Got` read (the filter then fails closed on it); if every feed raised, `FeedUnavailable` with the reasons joined by "; ". `bot_loops.deps_for` builds `Market(FallbackFeed([TastyFeed, SchwabFeed]))`, so a Schwab bot's filters still read when TastyTrade is down.
- **`bot_filters.check(market, bot, now)`** (Tracker2's `guards.vix_level_ok`, `vix_overnight_ok`, `vix9d_ratio_ok`, `technical_filters_ok`): in that order, the first that fails wins; a filter that's off, or on with nothing set, reads nothing. Returns `None` or `Skip(reason, unavailable)`. The reasons name the broker that answered (`got.source`), e.g. "no VIX price from Schwab". Prices: the latest trade, refused when missing or more than 5 minutes old; VIX's overnight pair from today's `Summary` only and the open of the 09:30 1-minute bar (none, with later bars there, is "no VIX 09:30 bar from Schwab", unavailable; the intraday move's open likewise), trusted only once the 1-minute history is complete (DXLink sends it newest first; waits up to 60 s; cached per day once both are read); technicals and the intraday move share one read (`_snapshot`: the price, daily bars from 300 days back unless cached, 1-minute bars from 5 days back; 60 s wait for the first bar before 09:31, else 10 s). Daily closes are cached per symbol and day only when complete and at least 199 long. Too little history for a period is "unavailable", as are an incomplete history (daily, or 1-minute when the EMA or the intraday open needs it) and no open yet (the intraday move's). **Nothing raises out of `check`**: any exception is "couldn't read the prices", unavailable.

### `bot_chase.py`
`chase(deps, request, first, plan, next_price, on_order=None, should_stop=None)` is Tracker2's `execution.chase_entry`: submit at the first price; every `interval_seconds` read the order (`get_order`); while it is still working, `orders.replace` it one step on; after the last try cancel it and confirm the cancel. It returns `Chased(status, order, log, message, broker_refused)` with status `filled`, `partial`, `missed`, `refused`, `unclear` or `preview`. A **partly filled order is never replaced** (the replace would be at the full size): the chase cancels the rest and returns `partial`. (`chase` is what exits use; the entry uses `chase_entry`, below.) Only a real `send` or `replace` result counts: a `preview` answer to a replace (the bot went to Paper mid-chase) stops the chase like a refusal, and the working order is cancelled. A refusal is never retried; an unclear send, an unclear replace, an unconfirmed cancel or a failed read-back stops the chase with `unclear`. Exits reuse it with their own price steps. Slice 3's hooks: `on_order(id)` hears of the send and every replace before any wait (Tracker2's `on_order_id`), so the caller records the working order on its row; `should_stop()` is asked after every wait, and a yes cancels the order, confirms the cancel and returns `stopped` (or `filled` if it filled first; an unconfirmed cancel is `unclear`). A `next_price` equal to the current price leaves the order working for another interval with no replace (the natural stage, when the natural hasn't moved). **A hook that breaks never strands an order:** a `should_stop` that raises (a database hiccup) is logged and counts as "not asked", so the chase carries on; an `on_order` that raises is tried once more (`_recorded`), and if it still fails the chase stops ("Stopped chasing: couldn't record the order"), cancels that order and confirms it like any other ending (`missed`, `partial` or `filled`; `unclear` only if the cancel can't be confirmed). **A cancel is read back up to 3 times, 1 s apart** (`read_after_cancel`, `CONFIRM_READS`; the wait is `deps.sleep`) before it counts as still live. **A close the broker cancels at once is sent again, once** (decision 0085, Tracker2 e7ab1a95's `_may_retry`): when the chase's first order reads back `cancelled` on its first read with nothing filled, no `replaced_by`, not a market order, and while its instrument's session is `regular` (or `futures`) (`_cancelled_at_once`), the same order goes out again at the same price through `orders.submit` (the central check), `on_order` hears of it, and its read doesn't use up a try. A rejected order, a later read, or a second cancel at once is not retried. If the second send is refused or previewed, the chase ends `missed` with the cancelled order and "Stopped chasing: …"; unclear is `unclear`. **A dead replacement re-reads the order it replaced** (Tracker2 8dce236f's `_replaced_order_fill`): a read that finds the replacement gone with nothing filled (TastyTrade accepts a replace, then rejects the new order with "Received a fill on the original order") reads the replaced order once more, read-only (`_replaced_fill`, never a cancel); if it filled the chase ends `filled` with that order, if it part-filled and is done the chase ends `partial` with it; otherwise, or if that read fails, the chase ends `missed` as before.

`chase_entry(deps, request, first, plan, next_price, on_tranche, on_fill)` is the entry's chase in units (Tracker2's `execution.chase_entry`) and returns `Entered`. A partly filled order is never replaced: it is cancelled and the cancel confirmed (unconfirmed: `unclear`). What filled becomes a tranche of the run the order was sent under, and `on_fill(run_id, order)` records it immediately, so a later failure can't lose it. If units and tries remain, `on_tranche(n, rest)` creates the child run and a fresh order for the rest goes out under it, at the current (already conceded) price, **on the same attempt counter**: `max_tries` covers the whole entry. A tranche that is refused or only previewed stops the chase ("short" if anything filled). An exception between tranches ends it as `short`; during an order, `unclear`. `Entered.fills` are the (run id, order) pairs; their exits are the caller's to place. Statuses: `filled`, `short`, `missed`, `refused`, `unclear`, `uneven`, `preview`.

### `bot_exits.py`
All orders go through `services/orders`. While Freeze is on, nothing is sent (`_frozen`).

**Closes run in the background** (slice 3; Tracker2's `close_jobs.begin_close` and `enqueue`). `EXITS_LOCK` is a re-entrant lock taken by each step of `monitor_pass` (per exit in its loops), by `fire_target`'s claim and by every re-arm a close's job makes; every order sent as part of a claim (a re-arm, the wing sales after a stop fills, the paired close, a target's placement) is sent with it held, so a side never has two closing orders. The one thing done without it is the monitor's read of each `working` exit's order (`_check` → `_read_working`, with no DB session open during the call), so a slow or down broker never holds up the other broker's stops and targets. The reading is then acted on under the lock (`_apply_check`) only if the row is unchanged (still `working`, the same order id, the same log length); a claim that landed meanwhile changed it, so the reading is dropped and left to the claim's own job, which reads the stop back itself. A target close and a chased wing run on their own thread through `BotDeps.background` (a daemon thread; tests pass one that runs inline), after the lock is released, so one run's chase never holds up another's exits. `FIRING` holds the id of every exit a live job is working on (a `firing` target or a `chasing` wing); recovery leaves those alone. One closing order per side: while a side closes, its stop is `cancelled` and its target `firing` (or its wing `chasing`), and the monitor touches only `working`, `pending` and `left` rows.

**Exits follow the run, not the bot.** Every exit order (stops, re-arms, wing sales, the target close) is sent with `run_live=run.live` and the run's `account_number` (`_run_and_bot`, `_request`). The order path then uses the run's live value instead of the bot's current one; switches, the closing rule, limits and the trading guard are unchanged, and the account check compares against the run's account. So flipping a Live bot to Paper mid-trade can't leave a side half-closed (Tracker2 keeps `BotRun.mode` per run the same way). **Only a real send, replace or cancel counts as placed** (`_placed`): a preview or refusal is never recorded as `working`; it's `failed` with an alert, or `pending` if Freeze refused it.
- **`place_protections(deps, run_id)`** (Tracker2's `exits.place_group_protections`): idempotent, it does nothing if the run already has exits. It **writes every exit row first, as `placing`**, then sends each stop and updates its row (`working` with the id, `failed`, or `pending` if Freeze refused it), so a crash part-way leaves rows the checks below catch. It waits for the broker to show every leg (up to `POSITION_TRIES` = 5 reads, 1 s apart; this is the guard from Tracker2's 2026-09-21 incident, when stray closing stops became opening orders). Per side it then adds a **stop** (stop-market buy-to-close on the short only, GTC; the trigger from `stops.stop_calc`, its arithmetic in the exit's `log`; a trigger with a `problem` is never sent: the row is `failed` and it alerts) and an **armed target** (`limit` = the close-at cost from `stops.target_limit`; one that can never be reached is `failed` and alerted, and the stop stands). The entry credit for the styles is the run's `fill_credit`, else its `target_credit` (Tracker2's `exits._entry_credit_for_basis`). The stop's `log` holds `stop_calc`. A side's refused stop never touches its target. The wings' quotes are subscribed so a fresh bid is there when a stop fills. If the legs never show, nothing is placed and it alerts. A refused stop alerts. A side whose fill has no price (the brokers' `_average_fill` skips unpriced fills and returns `None` when none are left) gets no stop or target, with an alert, rather than arithmetic from $0. Stops held by Freeze alert once ("stops waiting for Freeze").
- **The monitor** (`monitor_pass`, every 30 s, each step under `EXITS_LOCK` but the order reads, not while frozen): first recover targets a crash left `firing` (below) and wings it left `chasing` (`_recover_chasing`: `working` if the row has an order id, so the monitor reads it, else `failed`; it alerts either way); then for each `working` exit, read its order; then place `pending` stops (re-read under the lock: one a claim took since is skipped; `rearm(first=True)`: the position check, then the send; not counted as a re-arm). So stops refused while frozen go out once Freeze is off. **Stop filled** (`_stop_filled`, `remainder.handle_stop_fill`): cancel the side's armed target, then deal with the wing by the side's `on_stop_remainder` (`exit_math.remainder_mode`, which turns "leave" into a sale while it is paused). **The wing is sold at the size actually held**, capped at the trade's size for the side; an unreadable position tries the full size and lets the central check decide; no wing held records `expired`. The ways: `_sell_now` (`close_market`, `remainder.close_long_leg`) sends a **market** sell only if the long has a fresh bid (`_bid`: a quote under 30 s old), otherwise, or if the broker turns the market order down, `_one_tick` offers it at one tick ($0.05 on SPX), which still sells at the bid; `_sell_at_limit` (`close_limit`) rests at the side's price or the live bid on tick (`wing_limit`), else one tick; `_chase_wing` (`close_chase`) uses `bot_chase.chase` from the mid less the exit chase's start offset, one step lower each interval, then sells the rest now. It runs in the background: `_start_wing_chase` writes the wing's row `chasing` (`_new_wing_row`), adds it to `FIRING` and hands `_wing_job` to `deps.background`; `_run_wing_chase` records each order on the row (`_note_order`) and writes the outcome (`_finish_wing_chase`: the first result on the row, any more on their own rows), and the stop-filled alert (`_stop_alert`) goes out when it ends. `_new_wing_row` adds the row to `FIRING` before it commits it, so recovery never sees a `chasing` row with no job. A job that breaks leaves the row `working` (an order may be live) or `failed`, and alerts; `left` writes a wing row in state `left` and sells nothing. A refusal by the central check is final and is not retried at one tick; an unclear chase result sends nothing more; but a chase whose first send the broker turns down (`Chased.broker_refused`: nothing is out) is sold now, as Tracker2's `close_chase` fallback. Each wing is a `wing` exit row (a chase can leave two: the chased part and the rest sold now) with its steps in `log`. The alert says what happened. **`_sell_left_wing`** runs from `monitor_pass` when "leave" is paused: it closes the `left` row first (so a wing is never sold twice), then reads positions (unreadable: puts the row back for the next pass) and sells with `_sell_now`; a wing past its expiry is recorded `expired` quietly, with no alert. If the sale isn't placed, the alert says the wing wasn't sold, with the last answer; if anything breaks after the row is closed, it alerts and leaves the row closed (an order may be out). Likewise anything that breaks in `_stop_filled` after the stop is recorded filled alerts "a stop filled but the wing wasn't handled". The other side is untouched. **A stop cancelled or rejected without the app asking** is re-armed.
- **Re-arming** (`rearm`, Tracker2's `rearm_trade`): at most `REARMS_PER_DAY` (3) a side a day, then alert. Stops are **re-armed at the size still open** (`min(held, contracts)`). Position gone: the exit is `expired` and the side's target cancelled. **Expiry evening:** on or after the option's expiration date (from its OCC symbol), once that day's session has closed, the broker expires the GTC stops on that option; `rearm` then marks the stop `expired` (and the side's target cancelled) with no order and no alert. A group whose far legs outlive it is then the settle step's (slice 14). **Unreadable positions never expire a stop**: the stop is marked failed, the target stays armed, and it alerts.
- **The watch** (`watch_pass`, every 2 s, regular session only): for each `armed` target, subscribe to its two symbols and read the quote stream. Targets use the group's **natural value** (`exit_math.group_value(…, natural=True)`): each sold leg at its **ask**, each bought leg at its **bid** (a missing or zero bid counts as 0), not mids. Every sold leg's quote must be fresh with a positive ask; a bought leg's quote that exists must be fresh too (`exit_math.natural_fresh`; with `quiet_ok` from `quotes_live` when every leg's quote is there and its stream is live, so a quiet quote counts up to `exit_math.QUIET_MAX`, 300 s, as for the watch rules: #202). The bot's `underlyings.watch_symbol` is subscribed for that check. The cost must be at or below the target's `limit` for `CONFIRM_PASSES` (2) passes in a row (counted in `_breaches`). A target without fresh prices for `watch.STALE_ALERT_AFTER` (60 s) is logged once per episode as a WARNING, "bot target N: profit target paused, no fresh quote for 62s (not alerted) | legs: … | streams: …" (`_track_target_stale`, `bot_exits.stale_detail`), never alerted, and its recovery is silent (#203, Tracker2's `QUIET_STALE_KINDS`: a paused take-profit only delays a profit; stops and watch rules alert on their own).
- **Firing a target** (`fire_target`, once per side): the **claim** (`_claim_target`, under `EXITS_LOCK`): if the side's stop has already filled, the target is cancelled. Otherwise mark the target `firing`, mark the side's `working` or `pending` stop `cancelled` before the cancel (so the monitor won't re-arm or place it), and add the target to `FIRING`. Then `_target_job` runs on `deps.background` (if the thread can't start, `_recover` puts the stop back): `_close_side` cancels the stop and confirms with `get_order`, then sends a two-leg closing limit and chases it with the exit chase, recording each order on the target (`_note_order`). A stop that filled first, or a cancel that isn't confirmed, drops the target (and alerts if unconfirmed) and leaves the stop to the monitor. The close's own fills are counted in `_Close` (Tracker2's `FillLedger`: the only evidence a leg is closed). Endings: filled (`_closed`); **unclear** (`_unclear`: nothing more is sent and the stop is not re-armed, a second closing order could over-close; it alerts to check the broker); cancelled by you (`_cancelled`, below); otherwise by the exit chase's `exhaust_mode`: `give_up` (`_give_up`: `failed`, the stop re-armed under the lock for what's open, alert), `keep_conceding` (below) or `natural_then_leg_out`:
  - **`_natural_then_leg_out`** (`exit_chase.natural_stage`): for `natural_minutes × 60 / interval_seconds` tries (at least 1), a fresh two-leg order for the units left at the current natural (`_natural`: fresh quotes, a positive short ask; `exit_math.natural_price`), chased with `next_price` following the natural (unchanged: no replace). No fresh quote: wait an interval. A partly filled order is cancelled by the chase and a fresh one goes out for the rest; legs that filled unevenly go straight to the leg-out. Refused or preview: give up; unclear: `_unclear`.
  - **`_leave_bidless_longs`** (`close_jobs.select_close_legs`, decision 0065, #157): with the exit chase's `ignore_bidless_longs` on, right after `_size_close` (a target: before its own price), the bought legs with no fresh bid above 0 (`_bidless_longs`, `_bid`) are dropped from `close.legs`, so no stage (chase, keep conceding, natural, leg-out, market) ever sends them; sold legs are always closed. Never for a close you started by hand (`kind` "close", `by` None; `manual_close._settings`) or a partial one (`units` under `open_at_start`; `scale_out`). The close's log gets a `left` stage (`left`: the symbols, `why`: "no bid"), which the run's timeline shows as "Left <leg> to expire: no bid". Every leg left: nothing is sent and the close gives up with that reason. The left legs stay open in the Journal until expiry settles them; the side reads closed once the close fills, so no integrity check flags them.
  - **`_keep_conceding`** (`KEEP`, `exit_chase._Chase.keep_conceding`, decision 0065): after the single-leg switch to market (which wins first) and never for `_must_close` (a watched stop's close still goes natural, then legs out). From the chase's last price (`_last_price`, read from its log), one `_chase_step` further each round and each interval, clamped to the fresh `_natural` (never worse: `max`, since higher is better for a close either way); no natural quote: the step alone. Each round is one `chase` with a session's worth of tries and `should_stop` on Cancel or the session's close; an equal price keeps the order (no replace). Filled: `_closed`; partly filled: a fresh order for the units left, legs uneven: `_leg_out`; stopped: `_cancelled` if asked, else `_give_up("the session ended")`; refused/preview: give up; unclear: `_unclear`.
  - **`_leg_out`** (`exit_chase.leg_out`): positions read once (`_positions`; unreadable: give up). If the broker holds less of the short than the close hasn't bought back, someone else changed it (`NOT_ATTRIBUTABLE`): give up, nothing legged out. Then **`_buy_back`** (each sold leg in turn; slice 13): a single-leg buy-to-close from the short's mid plus the start offset (`exit_math.buy_limit`; no mid: its ask; no fresh ask: give up), one step more each interval, then **at market** for the rest. The market order's id is kept in memory (`_Close.progress["live_order"]`) the moment it is sent, then recorded on the target (`record_order`, tried twice). If it can't be recorded, the close ends `_unclear` ("a market order buying back … may still be working"); if anything breaks before it is recorded, `_recover` gets the id and puts nothing back (`market_live`). Either way no stop is re-armed over a possibly live market buy. It is read back up to 3 times (still working, or unreadable: `_unclear`, the wing not sold). The wing is sold only once `_Close` shows the whole short bought back by the close's own fills (`SHORT_NOT_ATTRIBUTABLE`), as a chased wing (`_new_wing_row`, `_run_wing_chase` with `in_session=True`, sized to what's held), and the target is `filled` ("legged out"; if no wing is held, the alert says the wing wasn't held). Once the session is over, the wing is not sold: the target is `filled` and the alert says the wing wasn't sold; and if the session ends during the wing's chase, what it didn't sell rests at one tick (`_one_tick`), never at market.
  - **Never past the close** (`_session_open`, the regular session): checked before the natural stage, each natural order, the leg-out and the short's market order; once it's over, give up (on expiry evening the re-arm marks the stop expired quietly).
  - Every stage is in the target's `log` (`_stage`: `chase`, `natural`, `leg_out`).
- **Cancel a running close** (`request_cancel(session_factory, run_id, exit_id, now)`, Tracker2's `close_jobs.request_cancel`): a conditional update sets `cancel_requested_at` only on the run's target while it is `firing`. The job checks it (`_asked`) before the first close is sent, after every wait (the chase's `should_stop`) and between stages; `_cancelled` (`stop_and_rearm`) marks the target `cancelled` ("cancelled by you: closed k of n"), re-arms the stop for what's open and alerts "Close cancelled". The chase only reports `stopped` once its cancel is confirmed; an unconfirmed one is `unclear` (no re-arm). After the leg-out has sent the short at market or bought it back, it no longer applies; `cancel_reaches(session_factory, exit_id)` says so from the target's `log`, and the run page's message then says Cancel can't stop the close now. A crash part-way goes to `_recover` (the bot's name is loaded inside its own `try`: an alert always goes out), which fails the target and works out whether the old stop is still there, filled, or has to be put back (`_settle_old_stop`); when it can't be sure (a read that keeps failing, a re-arm that fails or raises), the alert says "That side may have no stop. Check your broker." A stop cancel the order path refused (never sent) drops the target and leaves the stop working. Ids of targets being fired are in `FIRING`; at startup (`recover_targets`) and on each monitor pass, a target left `firing` that isn't in `FIRING` (the app died mid-target, after marking the stop cancelled) goes through `_recover` too. `_recover` first settles the close's own recorded order (`_settle_close_order`): working, it is cancelled through the order path and read back; **filled**, the target is `filled` and the stop stays cancelled (`_recovered_filled`; if the close was legging out, the alert says the wing may still be open); **still live or unreadable**, the target fails and nothing is re-armed ("the close may still be working"). Only then is the stop read back, put back to `working` if it may still be working or has filled, and re-placed only if the broker confirms it's gone. **A stop that was never placed** (claimed while Freeze held it `pending`; `rearm` clears the old order id when Freeze holds a re-arm, and the claim clears any id left on a `pending` stop) goes back to `pending`, never `working`: the next monitor pass places it, and the alert says the side has no stop until then. The close's order is read back after its cancel with `read_after_cancel` too.

### The timed close and time actions (slice 4)
- **`bot_timed.py`** (Tracker2's `timed_close.fire_timed_closes`, `time_actions.fire_time_actions`): both passes run from the monitor loop. `_open_runs` picks `filled`/`partial` runs with fills, not in `ACTIVE`, whose nearest expiration isn't before today, of a bot with a close time (or ticked time actions).
  - **`timed_pass`:** on a session day, for each run `timing.timed_close_due` says is due, each side with no `timed` row created today (New York date; once per side per day, whatever its outcome, `_fired_today`) and in state `open` is fired with `bot_exits.fire_timed`; a `busy` side, or Freeze on, waits for the next pass. Once the session is over (`"over"`), an `open` side with no `timed` row today gets one in state `missed` (the group's columns from `bot_exits.group_columns`, sized in its open units) and the run alerts once ("timed close missed").
  - **`actions_pass`:** not while Freeze is on. For each row `timing.action_due` says is due, `bot_exits.apply_time_action` on each side; one alert per row and run if anything wasn't applied ("time action 1 not fully applied", naming each side's notes; it won't be tried again), and one if it fired late. A side whose read breaks before anything is sent isn't recorded and is tried again next pass, alerting once per run, row and side ("couldn't run", `_BROKEN`); a move that breaks part-way is recorded `failed` with a note to check the broker. A run whose timed close can't be started alerts once a day ("timed close failed", `_FAILED`; Tracker2's `_write_error_row`) and is tried again next pass.
- **`bot_exits.fire_timed(deps, run_id, position, note)`:** the claim (`_claim_timed`, under `EXITS_LOCK`): only an `open` side (`timing.side_state`); a new `timed` row `firing` (the run's symbols, the side's contracts), the side's armed target and its `working` or `pending` stop marked `cancelled` with the event `cancelled for the timed close` (`CANCELLED_FOR_TIMED`), the row's id into `FIRING`. Then slice 3's `_target_job` on `deps.background`. `_close_side` reads the row's kind into `_Close.kind`: for a `timed` row, after the stop's cancel is confirmed, `_timed_start` reads positions (unreadable: give up), sizes the close to the short still held (none: the row `expired`, nothing sent; the short gone but its wing held: the row `failed` and "timed close not done", nothing sent) and prices it at `exit_math.group_mid_close_price` (no mid: `_natural`; neither: give up), logging a `timed` stage. Its first chase stops at the session's close (`should_stop` also asks `_session_open` for a `timed` row only; a `stopped` that wasn't Cancel gives up "the session ended": the stop goes back, or expires quietly on expiry evening). Everything after that is the target close's: the chase, the exit chase's ending, Cancel (`request_cancel` takes `CLOSES`: `target`, `timed`), `_recover_firing` (both kinds, either cancelled-for event). The alerts say "timed close" (`_Close.what`). **The target goes back** (`_restore_target`) whenever the timed close doesn't close the side and nothing of it is live: give up, Cancel, the stop's cancel not sent or not confirmed (`_timed_not_done`, "timed close not done"), and `_recover` outcomes in `_NOTHING_LIVE`; armed again sized to what's open, never on a side that's closed. A partial close re-arms it for the rest.
- **`bot_exits.apply_time_action(deps, run_id, position, action, number, late)`** (`management.apply_override`), under `EXITS_LOCK`: returns `busy`/`closed`/`done` (nothing recorded) or writes one `action` row, `filled` (everything moved) or `failed`, whose `log[0]` holds `sig`, `rule`, `number`, `late` and `notes`. **`_move_stop`:** the side's latest `working`/`pending` stop; the new trigger from `stops.stop_calc` with the side's style at the row's % (a $ or closing-order side uses `leg_premium`), overlay off; a `problem` isn't applied. Then, before anything is cancelled, the live check (Tracker2's `management._group_stop_live_check`): the short's fresh ask, waited for in `apply_time_action` before anything is touched (`_fresh_ask`: up to `QUOTE_WAITS` = 3 reads, 1 s apart; `place_protections` subscribes every leg, the shorts included, so the stream has it). With none, nothing is touched or recorded: `waiting`, tried again next pass, alerted once per run, row and side ("waiting for a price", `bot_timed._WAITING`). A new trigger at or below the ask is refused with the old stop still working. A `pending` stop just takes the new trigger. A `working` one is first marked `cancelled` with the event `MOVING_STOP` (recovery's marker), then cancelled through the order path and read back (`read_after_cancel`); filled first, not confirmed, unreadable, or the cancel not sent: it goes back to `working` and nothing moves. Once it reads cancelled, the row is written `pending` at the new trigger with no order id, then placed with `rearm(first=True)` (sized to what's held; not counted as a re-arm; nothing held marks it `expired`). A placement refused leaves it `pending`, so the monitor's next pass places it (once more, first=True), and the alert says the side has no stop until then. If anything breaks part-way, `_broke_note` (from the move's `progress` and the stop row's actual state) says the old stop was cancelled and no new one exists, and promises the next check only while the row is `pending`. **`_recover_moving`** (each monitor pass and at startup, under the lock, so never during a live move): a stop `cancelled` whose last event is `MOVING_STOP` is read back: working, filled or unreadable: `working` again; gone: `pending` and placed again at its old trigger (the time action, never recorded, runs again); it alerts "a stop move was cut off" (an unreadable old stop is "couldn't be confirmed", never "still in place"). **`_move_target`:** the latest `armed` target gets the new `limit` (`stops.target_limit` at the row's % on the group's entry per unit, so any group, credit or debit; its `_breaches` count cleared); a group with no armed target gets a new armed one, with the group's legs, anchor and kind. Slice 13: the action row's columns come from `group_columns(session, run, position, rows)` (also used by `_claim_side` and the missed timed row): the legs per unit, the anchor and kind as the stop or target recorded them, else `group_kind` on the group's sides.

### Schwab bots (slice 11)
**No switch.** Slice 11 put Schwab bots behind `SCHWAB_TRADING_ENABLED`; decision [0059](../decisions/0059-schwab-bots-need-no-switch.md) removed it. `validate` accepts any broker in `BROKER_NAMES`, and `bot_entry._guard` doesn't ask which broker. Schwab's refresh-login reminders mention bots only while a Schwab bot exists (`bot_loops.login_pass`).

**The run's broker.** `bot_entry._claim` writes `BotRun.broker`. In `bot_exits`, `_Run.broker`, `_client(deps, broker)` (LookupError when not connected; every caller treats that as unreadable) and `_broker(deps, run)` replace the old TastyTrade-only client: positions (`_positions(deps, run)`, `_legs_show`, `_held_of`), `get_order`, `working_orders`, and every `orders.cancel` and `_request` use the run's broker. `bot_manage` and `bot_loops._settle` (reconcile) likewise. `orders._bot_facts` checks a bot's own run against the run's broker as well as its account.

**Exits at Schwab** (decision [0060](../decisions/0060-schwab-bots-rest-their-exits-at-schwab.md), replacing 0037's watched stops): a Schwab run's exits follow exactly TastyTrade's rules (`exit_plan.plan_group` ignores the broker). A credit group with one sold leg that chose Stop rests a single-leg GTC stop market order on its short at Schwab (`_stop_request` → `orders.submit` → `trading/schwab.order_body`: `orderType` `STOP`, `stopPrice`, one `BUY_TO_CLOSE` leg, `GOOD_TILL_CANCEL`); a group that rests its target rests one GTC closing limit (`NET_DEBIT`/`NET_CREDIT`) at Schwab (`_send_target`), and the app holds its stop on the short (`app_held`, worded by `watched_short(run)`); every other stop is watched, as on TastyTrade. Schwab reports a stop not yet triggered as `AWAITING_STOP_CONDITION`, which `broker_order` reads as working; `REPLACED` reads as cancelled. A stop or target move is never a replace: `_move_stop` and `change_resting_target` cancel through `orders.cancel`, read the old order back (`read_after_cancel`) and place the new one, at either broker. `orders.submit`'s one check (`trading/check.py`) applies unchanged: a single-leg stop passes, and `trading/orders.Order` refuses a stop of more than one leg before any broker sees it. User-facing words name the run's broker (`broker_name(run)`, `rests_words(run)`, `run_broker_name(deps, run_id)`).

**Watched stops** (`bot_exits`; slice 11, now only for app-held rows; Tracker2's `exits._record_armed`): `WATCHING`, `STOP_LIVE = ("working", "pending", "watching")`. Whether the app holds a stop is read **only from the row**, never the broker: `holds_short(row)` is `row.app_held`, `app_watches(row)` is `row.watched or row.app_held`. A Schwab stop from before 0060 is app-held by migration 0036, so everything below keeps applying to it until its trade closes.
- `place_protections`: an app-held stop becomes `watching` (log `watched_short(run)`), **even when the legs haven't shown** (nothing is sent until it fires, and the close sizes itself then); its targets still need the legs shown ("profit targets not set … Its stops are watched by the app").
- `rearm` → `_watch_stop` for an app-held stop once positions are read: held 0 still expires it; otherwise `watching`, sized to `min(held, contracts)`, `rearms` + 1 unless `first`; **unreadable positions keep it watching** at its size. Expiry, exits-off and the re-arm limit come first, as before.
- `_move_stop` treats `watching` as `pending`: the live-ask check, then just the new trigger, note "stop 4.80 → 6.20 (watched by the app)". `_claim_side`/`_claim_target` pull it like a pending stop (no order id). `_close_side` has nothing to cancel. `_settle_old_stop` puts a watched stop back with `rearm(first=True)`. `monitor_pass` expires watching stops past their option's expiry with the side's target (`_expire_watched`), quietly.
- `bot_manage` (change stop, exits off, the side view) and `bot_watch` (a profit action's move) look up a side's stop by `STOP_LIVE`; exits off on a watching stop is `EXITS_OFF` at once (no order); exits on re-watches it through `_place_pending` → `rearm`.
- `fire_close(…, detail=)` logs the reading that started a close (`reading`).

**`bot_watched_stops.py`** (the watch; Tracker2's `watch_loop._armed_exit_pass`, `_fire_armed`, `_track_stale`): `watch_pass(deps)` is the `bot-watch` loop's second step. Never raises. Since slice 13 it also watches every group the app watches on its P&L, on TastyTrade and Schwab alike (see [Any same-day structure](#any-same-day-structure-slice-13)); what follows is a stop held on its short (`app_held`: a group whose target rests, or a Schwab stop from before decision 0060).
- Regular session only (`session_now == "regular"`); outside it, or with nothing watched, streaks and stale clocks are cleared (`_quiet`). Stops: `watching` rows whose short isn't past expiry (`_stops`).
- **Lapse** (`_check_lapse`): `watched_stops.lapse_since(last watch, now, today's 09:30, earliest stop's created_at)`; a gap is alerted once per bot ("stops weren't watched", from–to New York, "Check your broker") and the last watch moves on. The last watch is in memory every pass and written to `_watched_stops_at` at most every 15 s (`_beat`). **`recover(deps)`** (startup, `bot_loops.recover`) runs the same check, including stops that expired today, ending at today's close at the latest.
- **Per stop** (`_watch_one`): the hub's quote for the short (a read that raises is no quote; subscribing every pass is local and idempotent), `watched_stops.evaluate` with `quiet_ok` when the quote's stream is healthy (`bot_exits.stream_healthy`: status "streaming" and the underlying fresh from that source; a group's every leg: `bot_exits.quotes_live`; then up to `QUIET_MAX`, 300 s, Tracker2's `QUOTE_QUIET_MAX_SECONDS`, `exit_math.QUIET_MAX`), `_track_stale` (a minute stale or bad alerts once "stop not watched (stale price) … no stop at Schwab", and "stop watched again" when it's back), then 2 passes in a row (`_streaks`).
- **`_fire`:** Freeze on → nothing sent, alerted once per stop ("stop reached, Freeze is on"). Under `EXITS_LOCK`: the row still `watching`, exits not off; 3 closes `by="stop"` today on the side (`_closes_today`) → the stop `failed`, "stop left to you" (no stop); else `bot_exits.fire_close(run, side, group_units, group_units, by="stop", detail=reading)`. Claimed → "stop reached, closing the side"; not claimed on a held side → "stop reached, group held back" (`_say_held`), worded by `_held_reason` (a profit target may still rest, an earlier close may be live, a stop move was cut off, or the group's exits are still `placing`) and said once per stop and reason (`_held_said` holds `(stop id, reason)`), so a later, different hold is said too. The close is `by=WATCHED_STOP_BY`, and `bot_exits._must_close` sends it on to the natural price and the leg-out whatever the bot's exit-chase ending (the controller's ruling on review I-3); its put-back is `rearm(first=True)`, never a re-arm. A watched stop past the re-arm limit alerts "stop no longer watched". A tranche run copies its root's broker; saving a bot at another broker disarms it and sets it to Paper; arming, going live and a live Preview order need `understood` only when `definition.app_watched(bot)` (a group with an app-watched stop, on either broker; decision 0060). `schwab_login.check(bots=)` mentions bots only when Schwab bots are on or exist. The close is a slice 6 close: the exit chase and its ending; what it leaves is re-protected by `_protect_rest` (watched again), so a still-breached stop fires again, up to the 3.
- In-memory state is per process; `reset()` is for tests.

**`schwab_login.py`** (Tracker2's `schwab_token_alerts`): `check(session_factory, credentials, now, notify)`: `core.alerts.schwab_reminder(credentials.schwab_login_expires_at(), now)` is `48h`, `12h` or `expired`; each is sent once per login (`_schwab_login_reminded`; a level counts the earlier ones as said), as "Schwab login needs you: …" to `/settings#brokers`. No login (gateway mode, not connected): nothing. Never raises. `bot_loops.login_pass` runs it every 10 minutes (`schwab-login` loop).

### Managing one trade (slice 6)
**`bot_manage.py`** (Tracker2's `management.py`, `manual_close.py`, `override_tags.py`) holds the actions; the order machinery stays in `bot_exits`. Each action takes `EXITS_LOCK` (held across the broker calls, as `apply_time_action`), reads the side (`_read`: the run `filled`/`partial` with fills, the side's rows, its open size, exits-off) and refuses before touching anything when the side is closed or busy (`timing.side_state`), returning `Outcome(ok, message)`. A refusal saves nothing; what took effect is upserted into `bot_trade_overrides` (`_upsert`, `_save`).
- **`change_stop(deps, run, side, text)`**: refused with exits off or no stop row. The short's fresh ask is waited for (`bot_exits._fresh_ask`; none: refused, nothing touched). A `working`/`pending` stop goes through `bot_exits._move_stop` with the marker `MOVING_STOP_BY_YOU` (cancel → `read_after_cancel` → `pending` at the new trigger → `rearm(first=True)`; would fire at once, not confirmed, filled first or not sent: nothing moves). A `failed`/`cancelled` stop gets a new one (`bot_exits.place_stop_at`: the same arithmetic, `_moved_calc`, the ask check, then `_place_pending`), its size first capped at the side's open size. `stop_pct` is saved once the stop's trigger changed. A breakage is alerted with `_broke_note`.
- **Held back** (final review): `change_stop`, `close_part` and `exits_on` refuse with `MAYBE_LIVE` when `_maybe_live(side)`: the latest stop is `cancelled` with a last event in `_LIVE_MARKERS` (a close's `CANCELLED_FOR_*`, a `MOVING` marker, `TURNING_OFF`), or the side's latest close (`target`, `timed`, `close`) is `failed` with live evidence (`_live_evidence`: an `unclear` event, `close_order: live`, a `market_order`) and is no older than the stop row. `change_stop` replaces a non-working stop only when `_replaceable`: `failed`, or `cancelled` with "broker shows …" last. Its size cap is written only after the ask check. `exits_on` writes `exits_off` false and the stop `pending` at its (old or new) trigger in one transaction, then `_place_pending`; a typed % on a side with no stop is refused. `_undo_off` leaves the targets cancelled when the stop filled first.
- **Settling a held-back side** (re-review): `bot_exits.held_back(rows)` (`close`: a stop cancelled with a close's `CLOSE_MARKERS` event, or a latest close `failed` with `live_evidence`; `move`: a `MOVING`/`TURNING_OFF` marker, left to its own recovery) is what `_maybe_live` and `_claim_side` check, so no close (a timed close included) claims such a side. **`settle_held`** runs in `monitor_pass` (not while frozen) over sides with a cancelled stop or a failed close. **`settle_side(deps, run, side, asked=False)`** is conservative: it never sends an order, reads positions, closes the side or touches a stop, target or wing.
  - **Skipped** while any of the side's rows is in `FIRING` (a close job is still finishing).
  - **Held** while any working order at the broker touches the side's two legs, or a recorded close order (`broker_order_id`, logged `market_order`) may be working or can't be read. It alerts once per side (`_HELD_SAID`, keyed by run and side; not when `asked`).
  - **Released** otherwise: the latest close row gets the event `SETTLED`, which `held_back` honours (that close's live evidence and its `CLOSE_MARKERS` on the stop no longer hold the side). It alerts once: "<side> is no longer held back … The app didn't put a stop back — check your broker, then set a stop (or close) from the run page."
  - **After release,** `_replaceable` accepts a stop pulled by that close, so `change_stop`, `close_part` and `exits_on` work with their own checks. **`bot_manage.recheck`** (the run page's "I've checked my broker: re-check now", action `recheck`) runs `settle_side(asked=True)` under the lock and flashes its answer (held because …, or released: set your stop). `SideView.held` shows the yellow box and hides the other actions.
- **`change_target`**: `bot_exits._move_target` (re-price the armed target, or arm one at the side's open size); `target_pct` saved.
- **`exits_off`**: in one transaction the armed target is `cancelled` (`EXITS_OFF`), a `pending` stop `cancelled` (`EXITS_OFF`, id cleared), a `working` one `cancelled` with the marker `TURNING_OFF`, and the override `exits_off`. Then the stop's cancel (`_cancel_for_off`): confirmed cancelled → event `EXITS_OFF`; not sent, not confirmed, unreadable or filled first → `_undo_off` (stop `working`, targets `armed`, `exits_off` false; Tracker2's abort rule).
- **`exits_on(…, text)`**: refused unless off. The latest `cancelled`/`failed` stop is placed again at its trigger or the % typed, after the ask check (would fire at once or no price: refused, still off); `exits_off` cleared, the `EXITS_OFF` targets armed again (capped at the open size), the stop capped at the open size and placed (`_place_pending` / `place_stop_at`).
- **`close_part(…, text)`**: refused outside the regular session (`bot_exits._session_open`), under Freeze, on a preview run, on a closed or busy side, or for more than `min(broker short count, open size)`; then `bot_exits.fire_close`. Decision [0084](../decisions/0084-close-group-counts-single-contracts-of-a-lot.md) (#209): a group's unit is its ratios over their gcd, so one bot contract of a ×N one-leg group is N units of one contract and `close_part` already closes 1..N of them, re-protecting the rest by `_protect_rest`; Tracker2's `split_close` (sub-unit chase, rebasing `selected_legs`) has no counterpart. `SideView.unit` is `contract` on a one-leg group (the Close box says "of N contracts"), else `unit`.
- **`recover(deps)`** (startup and each monitor pass, under the lock, never raises): a stop whose last event is `TURNING_OFF` is read back: gone → `EXITS_OFF` (off, as asked); working, filled or unreadable → `_undo_off`. It alerts either way.
- **`sides(session_factory, run, bot)`** → `SideView`s for the run page; **`journal_chips(session_factory, entries)`** → `{position key: chips}` for the page's bot trades in a few queries, only the sides whose short is one of the position's legs (a split condor's half), each chip prefixed with its side's name when two sides have chips.

In **`bot_exits`** (slice 6):
- **The guard:** `exits_off(session, run, side)` / `off_sides`. `rearm` marks the row `cancelled` and sends nothing; `_claim_target` cancels the target; `_claim_side` refuses a timed close; `apply_time_action` records the action `skipped` ("exits were off"), so it's spent and never applied (or alerted late) once exits are back on; `_restore_target` restores nothing; `bot_timed._timed_run` skips the side (no timed close, no missed row).
- **`_claim_side(deps, run, side, kind, note, contracts, **logged)`** is the timed close's claim, shared with `close` (its event per kind, `_PULLED_BY`: `CANCELLED_FOR_TIMED`, `CANCELLED_FOR_CLOSE`). Its default size is `group_units` (the run's contracts × the group's gcd, less what `reduced` closes closed). **`fire_close(deps, run, side, quantity, open_size)`** claims with `contracts` = quantity and `open` in its log, then `_start_claimed` (shared with `fire_timed`) runs `_target_job`.
- **In the close job**, a `close` row is handled as a `timed` one: the early endings say "close not done" (`_timed_not_done`), `_timed_start` sizes it to `min(short held, quantity)` and records `open_at_start` = `min(short held, open size)` (in `progress` and the log), the chase stops at the session's end.
- **`_closed` → `_close_filled`:** nothing left (`open_at_start` − the close's own short fills) → `filled` (the side is closed); else `reduced` (`closed`: k), then `_protect_rest` sets the stop row's contracts to what's left and places it (`rearm(first=True)`, capped again by the broker's count, so never more than held) and `_restore_target` arms the target at that size.
- **`_give_up` / `_cancelled` → `_close_ended`:** `reduced` if anything closed (else `failed`/`cancelled`), then the same re-protection.
- **`_recover`:** a `close` whose order had filled → `_recovered_close` (`filled`, or `reduced` and re-protected); `_restore_target` for `close` as for `timed`; the alert says "close error". `_recover_firing` knows `CANCELLED_FOR_CLOSE`; `_recover_moving` knows both `MOVING` markers.
- **`apply_time_action`** (slice 6 changes): sized by `group_units` (a created target's size); a level it moves clears that level's `stop_pct`/`target_pct` on the override, so the chip doesn't go stale; rows are written by `_record_action`.
- **A cut-off `close`** (`_recover`): its job logs `done` with each stage, and `_settle_close_order` reports its last order's short fills (`seen`); if either shows fills and the order is gone, the row is `reduced` with `closed` (`_confirmed_done`), the stop row capped at what's left and the target restored at that size.
- **`_move_stop(…, marker=MOVING_STOP)`**; its arithmetic is `_moved_calc` and its placing `_place_pending`, both shared with `place_stop_at`.

### Watch rules and profit actions (slice 7)
**`bot_watch.py`** (Tracker2's `watch_loop.py`, `scale_out.py`): `watch_pass(deps)` is the `bot-watch` loop's second step (`bot_loops._watch`: the targets' `bot_exits.watch_pass`, then this, each on its own). Never raises.
- **When:** regular session only and Freeze off; otherwise every streak and stale clock is cleared and nothing is read.
- **Which trades** (`_trades`): runs `filled`/`partial`, live, with fills and `filled_at`, from the last 10 days, not in `bot_entry.ACTIVE`, not every leg past expiry, of a bot with `watch.rules_of` or a side with profit actions, with a side not closed. Their side states (`timing.side_state`), off sides, whether a `watch` row exists (fired once), and the profit actions done (`profit` rows' `number`).
- **Reading** (`leg_view`, `_spot`): each leg's hub quote (fresh: `exit_math.fresh`, after the fill and under 30 s old, or under `exit_math.QUIET_MAX`, 300 s, while the stream it came through is live: `bot_exits.stream_healthy` on the bot's `underlyings.watch_symbol`, which must have updated through that stream within 30 s; #202, Tracker2's `_quote_fresh`, decision 0081) and delta (`hub.delta`, under 150 s and after the fill, never the quiet rule); SPX's `last` by its `last_at` (30 s, never the quiet rule). A read that raises is no data. Paper's profit actions and watch rules read the same `leg_view`.
- **Whole-trade rules:** not while any side is busy (their streaks start again; the profit actions keep theirs). `watch.evaluate` over the open sides' legs; `_confirmed` keeps each rule's passes in a row and the first one's time in memory (`_streaks`: (passes, since); a pass that doesn't hold clears it) and fires on `watch.confirmed`: 2 passes, and for a rule that `watch.must_hold` (`position_delta`, `sl_ratio`, every `leg_delta:N`; Tracker2's `HOLD_KINDS`, #201, decision 0081) `watch.HOLD` (30 s) since the first. The underlying move, tested shorts and profit actions need the passes only. **`_fire`**: exits off read again; for each side not closed: off → left alone (said in the alert); otherwise `bot_exits.fire_close(deps, run, side, open, open, by=rule name)` at `group_units`; claimed → a `watch` row (`filled`, the rule, its reading, the close's id); not claimed → "a close is already running on it". One alert ("IC: S/L ratio exit", the reading, the sides closing). Nothing claimed: no row, so it tries again while the rule holds (alerted once), or, when every open side is off, "nothing closed" once.
- **Stale data** (`_track_stale`): any rule or action skipped "stale"/"incomplete" starts a clock per run; after 60 s one alert ("watch rules paused", naming them, then `_at_broker`: "Your stops at TastyTrade still work: Call side 4.80, Put side 4.80." from the run's `working`, not-watched stop rows, or "… no stop rests at TastyTrade for this trade."; #203, Tracker2's `_broker_stops`), and one when all read again ("watch rules resumed"). With the pause (alerted or not, once per episode) `_log_stale` logs a WARNING, `watch rules paused for run N: <each stale rule's detail> | legs: <symbol> quote=40s greeks=never src=tastytrade, … | streams: tastytrade=streaming (live), …` (`bot_exits.stale_detail`; Tracker2's `_log_stale_detail`), so the log tells a quiet option from a dead feed. "no_entry" (a run with no `entry_spot`) alerts once on its own.
- **Profit actions** (`_profit`): per group with profit actions, only while it's `open` and exits on, only the lowest-numbered action without a `profit` row, on the group's entry (`_Trade.entries`, `bot_exits.group_entry_of`) and every leg's fresh mid at its per-unit ratio (`watch.group_pnl_now`); 2 passes. `watch` and `profit` rows carry the group's columns (`bot_exits.group_columns`) and its open units. **`_fire_profit`** under `EXITS_LOCK`, the group read again (open, exits on, not done), counted in units (original = run contracts × the group's gcd, open = `group_units`): `n = watch.contracts_for(original, close %)`; `n` > 0 leaving < 1 → `profit` row `failed` ("skipped … nothing for the profit target"), alerted, never again. `n` > 0 → `fire_close(…, n, open, by="profit action N", then_stop={"pct", "by"} or None)`; not claimed → nothing recorded; claimed → `profit` row `filled` ("closing n of open (close id)") and an alert. `n` = 0 → **`_move_for_profit`** on the group (`bot_exits._group_of`): no working/pending stop or no fills → `failed`; `bot_exits.profit_stop_calc` (shared with `_then_stop`: `stops.level_calc` on a resting stop's anchor per contract of its ratio, `stops.watched_level` for a group the app watches); the anchor's `_fresh_ask`, or the group's `_live_pnl` for a watched group (none: nothing recorded, "waiting for a price" once); `bot_exits.level_problem` (a problem, not tighter than the stop in force, or where it would fire at once) → `failed`, nothing touched; else slice 4's `_move_stop(…, marker=MOVING_STOP_PROFIT, found=(calc, log), pnl=)` (a watched level is only rewritten, nothing sent); `filled`/`failed` with its note and an alert.
- **Final review fixes:** the opening pause (`watch.in_opening_pause`, Tracker2's `guards.in_opening_pause`: in the session's first 60 s nothing counts as fired, for every rule and action; Tracker2 exempts only its $ stops, which this app doesn't watch). `_fire` closes each side in `_fire_side` under `EXITS_LOCK` (exits off, `held_back` and busy read there with the claim), writes its `watch` row `failed` "starting the close" before `fire_close` and finishes it (`_finish`) after; a side that breaks doesn't stop the others and the alert says "PARTLY started … close it yourself". A profit action's row is likewise written before its claim or stop move and finished after, so a breakage never runs it twice. Profit actions are known by `ProfitActionDef.sig` (at | close % | stop), stored in the row's `sig` (an older row without one is matched by its number, `_action_sig`), so editing the list never re-runs or skips one. A "would leave nothing" action is recorded `blocked`, and no later action on that side runs (`plan`). A leg with no strike is stale for the tested-short rule. The paused alert's state clears with its clock (Freeze, outside the session, a run no longer watched); a pause of the delta rule alone is said once per bot per New York day (deltas come only from TastyTrade's stream). The stream stores only finite numbers (`core.quotes._decimal`).
- **In-memory state** (`_streaks`, `_stale_since`, `_stale_alerted`, `_once`) is per process; `reset()` is for tests.

In **`bot_exits`** (slice 7):

The alert adds "The stop moved 4.80 → 2.45 (profit action 1)". `_close_ended` (give up, Cancel) never moves it and says so. `_recovered_close` doesn't apply it (the old stop goes back).
- **`level_problem`**, **`group_entry_of(run, legs)`** (the group's entry per unit from the run's fills), **`MOVING_STOP_PROFIT`** (in `MOVING`, so `_recover_moving` puts a cut-off profit move right), **`_move_stop(…, found=)`** (a trigger already worked out).

### Any same-day structure (slice 13)
Decision 0039, issue #95. A bot is 1–4 legs (`MAX_LEGS`), ratios 1–10 (`MAX_RATIO`), in 1–4 groups (`MAX_GROUPS`), taking a credit or a debit (`premium_side`, shown as **Opens for**, until decision 0048 removed it; see "Trades take either side" below). Slice 13 kept every shape same-day; slice 14 adds other expirations (below).

**Sign conventions and units** (used in every signature below, and nowhere else with another meaning):
- Prices are signed, + a credit (`trading/orders.py`). A group's **entry** E is per unit, + a credit. Its **value** V is what closing costs now, signed like the entry (+ closing pays, − closing receives). **P&L** = E − V per unit; dollars = P&L × 100 × units. A close order's price is −V. A watched stop's **level** is a P&L per unit (≤ 0 when placed).
- A group's **unit** is its legs' bot ratios divided by their gcd (`exit_math.group_legs`, Tracker2's `exit_chase.ratio_quantities`): one unit of a 1×2×1 butterfly is 1, 2 and 1 contracts. Every group price is per unit. Units held = `run.contracts × gcd − closed units` (`bot_exits.group_units`). `BotExit.contracts` is group units on stop, target, close, timed, action, watch and profit rows, and contracts of that leg on wing rows. A resting stop sends `units × anchor.ratio` contracts. For a ratio-1 iron condor each of these equals the slice 12 number. `GroupLeg.ratio` is always per unit; `BotRun.legs[*].ratio` is always the bot's ratio; `group_legs` is the only place one becomes the other.

**`bots/` (pure):**
- `definition.rests_stop(sides)` / `BotDef.rests_stop(position)` (decision 0054, #123): only a group of exactly one leg, a sold one, may rest its stop. `lone_shorts_rest_stops(bot)` sets every other group's `broker_exit` to `target`; it runs where a bot comes in (`bot_store.read_form`, `bot_file.from_file`), the shapes start that way, and migration 0034 set existing groups so (switching off armed or live bots that had one: `Bot.notice`, alerted once by `bot_loops.send_notices` at startup, shown on the bot page until `set_armed` clears it). The form: a group of more than one leg posts a hidden `rests=target` with a "Stop watched by the app" note; **When its stop fills, also close** shows only on a lone sold leg; the remainder is "When another group's stop closes it", shown by `group_exits.js` on a group some pair select names.
- Leg groups (#120, OptionOmega's): under Use leg groups each group's name and ✕ and its legs as cards; ▲/▼ post `move-leg-N-up`/`-down` (`definition.move_leg`: the next group, never past either end; an emptied group stays). **Exit rows** (`bot_exits`):
- `exit_legs(row)` is the only reader of a row's legs: `legs` per unit, else (rows with empty `legs`: test fixtures, a row a crash wrote mid-upgrade) the old short/long pair at ratio 1 (`exit_math.row_legs`). `_anchor_leg(row)` reads `anchor_symbol` (ratio 1 for an old row); `row.watched` says the stop is watched on the group's P&L. `group_columns(run, position, rows)` gives a new row its legs, anchor and kind as the group's stop or target recorded them, else as `place_protections` would make them; the old columns get the anchor (or `""`) and the first other leg (or `""`).
- `_Group(legs, anchor, units, fills, entry, filled_at)` (`_group_of`) is what a move works on; `anchor` is None for a watched group. `group_entry_of(run, legs)` is its entry from the run's fills.
- `place_protections`, per group (decision 0048): `exit_plan.plan_group` says what rests. A group resting its stop gets a resting stop on its anchor, `units × anchor.ratio` contracts (a Schwab run's single-short stop is `watching` on the anchor's mid as in slice 11); a group resting its target gets one GTC closing limit for all its legs (`_send_target`) and a `watching` stop with `app_held` set (on its short, or `watched` on the group's P&L); the others arm their target for the watch as before. See "Trades take either side".
- **Stop fill** (`_handle_stop_fill`, Tracker2's `remainder`): the group's target is cancelled; every other leg still held (`_other_legs`: bought legs only; none for a naked short) is handled by the group's remainder mode, each on its own wing row and order, capped at this run's contracts of that leg less what profit actions closed. A chased leg chases on its own mid, stepping `max(step, tick)`.
- **`close_group`** (was `_close_side`; Tracker2's `close_jobs`, `exit_chase`): the stop cancelled and confirmed; a timed close or one asked for is sized by `_size_close` to what this run holds (each leg in whole units of its ratio; a leg held the wrong way refuses the whole close; some legs gone while others are held sends nothing and alerts; nothing held ends `expired`); a target closes the units it was armed for (the central check refuses any leg bigger than what's held). One closing limit over every leg, reversed (`_closing_legs`), at `group_mid_close_price` or the target's value, chased by `next_close_price`. A close that sends nothing puts the group's stop back (and a timed close's target) and alerts.
- **Leg-out** (`_natural_then_leg_out`, `_leg_out`): sold legs are bought back first, one at a time (`_buy_back`: from its mid plus the start offset, a step, at least its tick, more each interval, then at market); bought legs are sold (`_sell_buys`, each on its own wing row) only once the close's own fills prove every sold leg bought back. A multi-leg order never goes to market. `_stop_leg_out`: before any leg filled unevenly, the old give-up (the stop goes back); once any sold leg is bought back or the legs filled unevenly, `_left_to_you`: the close ends `failed`, no stop or target is put back (a close on a part-closed group would be refused "some legs gone"), and the alert names every leg still held and says nothing protects them.
- **Recovery**: a cut-off close is marked filled only when every sold leg's full size is proven bought back by its own recorded fills; otherwise it's left to you with an alert (`_leg_out_left` reads what a cut-off leg-out left). A crash between a short's buy-back and its wing's hand-off therefore ends "left to you" naming the wing (slice 12 marked it filled with the wing held).
- **`rearm`**: a resting stop goes back on its anchor only while the anchor is held **short**; it sends `min(units × ratio, held short)`. A watched group is watched again (`_watch_group`) while the run holds any of its legs the group's way, less what its wing rows still have to sell; it's never a re-arm and never counts toward the 3 a day.
- **Moves** (time actions, profit actions, the journal): `_moved_calc`, `_move_stop`, `place_stop_at` and `_move_target` take a `_Group`. On a watched group a move only writes the new level (`_move_level`), checked against the live P&L (`_live_pnl`, the watched stop's own reading rules): a level at or above it would fire at once and is refused (`_fires_at_once`). A profit action's move is never looser (`level_problem(pnl=)`); a time action and your own change from the journal may loosen a watched level, as they may a resting stop. `profit_stop_calc(g, pct, by)` is a profit action's new stop.

**`bot_watched_stops`** now watches every `watching` stop on **any broker**: a Schwab single-short stop on its anchor's mid (slice 11), and every row with `watched` true on the group's whole P&L (`_read_group`, `watched_stops.evaluate_group`). ### Trades take either side (decision 0048)
Issue #107. There is no **Opens for**: a trade takes the side its mid prices on, and each group chooses which of its two exits rests at TastyTrade (`BotDef` group field `broker_exit`, `stop` or `target`; the file's `rests`). Only one closing order can rest per group, and the app watches the other.

**The side.** `strikes.entry_price` at the mids is the trade's signed price (+ a credit); under `strikes.MIN_CREDIT` either way it's skipped (`too_close_to_even`). The text of what it priced as and what every group would set is `BotRun.priced` (`exit_plan.preview`); Preview order and the run page show it. A group with one sold leg that prices as a debit inside a credit trade is still refused (`strikes.inverted_group`). A trade that filled for a debit is read as such for its exits: `exit_plan.credit_fill(entry_credit, fallback)` (a fill that has no price counts as a credit, as every trade did before this).

**The table** (`exit_plan.plan_group`, spec section 2), the same on TastyTrade and Schwab (decision 0060; before it nothing rested at Schwab, decision 0037): a credit fill with one sold leg and a stop rests that stop on the short unless the group chose its target and has one; every other group rests its target, and the app watches its stop on the short's quote (`stop_on == "short"`, a credit's one sold leg) or on the group's P&L (`"pnl"`, decision 0039). A debit fill on a group that chose Stop is `fallback` (a stop can't rest on a debit): target rests, stop is watched, and `entry_alert` tells you; the run page shows each group's `FALLBACK_NOTE`. `exit_plan.CREDIT_ONLY` names the stop styles that don't translate to a debit fill.

**The resting target.** `place_protections` sends it through `_send_target` (one GTC closing limit, all legs; a futures run's path since decision 0043, now general); it is `working`, and `rested(row)` / `target_rested(session, run_id, position)` tell a resting target from an app-armed one (the row's state, or `{"rests": "target"}` in its log, which `change_resting_target` and `_restore_resting_target` also write). The broker's fill is seen by `_check` and recorded once by `_record_target_fill`; `_end_the_watch` then stops the group's watched stop in the same commit, so a crash between the two can't leave a flat group's stop watching. A target that ended without filling is `_target_ended` (a futures run's has no exit now and is said so; any other run's alert says what's left, and Restore places the target again through `_restore_resting_target`). Every "profit target not placed / gone" alert (the fill, `_place_pending_target`, `_target_ended`, `_put_resting_back`, `change_resting_target`) words what's left from one helper, `left_without_target(deps, run, position)` (futures: no exit; no live stop: no exit; else the stop resting, watched or waiting for Freeze), through `_no_target_alert`, which marks the run Needs you when no exit is left. The fall-back entry alert never says a target rests whose send failed (its level is cleared), nor that a stop is watched when there's none (`exit_plan.entry_alert` says "It has no stop.").

**A send with no clear answer.** `_send_target` returns the broker's `Unclear:` message as is (never "not sent"), and `sent_unclear(state, message)` tells it. Every caller holds such a row as an unclear change is (`_hold_unclear_send` → `_hold_target(doing=…)`: `failed` with `TARGET_UNCLEAR`, Needs you, "profit target unclear"): `place_protections`, `_place_resting_targets` (futures), `_place_pending_target`, `place_target_again` (a plain refusal is now logged "not placed again" on its row), `_put_resting_back` and `bot_rearm._restore_resting_target` (on a new row when the old one isn't reusable). `bot_loops._check_run_exits` holds a stale `placing` row the same way when it is a resting target (`rested(row)`, or a `pt_only` run's), so `target_may_rest` and `held_back` see it and no close is claimed on the group.

**The stop the app holds on its short.** A TastyTrade stop row whose group rests its target has `app_held` true; `holds_short(run, row)` is `watched(run) or row.app_held` and is what `rearm`, `_settle_old_stop`, `_must_close` and `bot_rearm._stop_check` read, where they read only `watched(run)` before. `WATCHED_SHORT` is the note a stop row carries for it. Without the mark, a close that gave up would send the stop as a second closing order on a group whose target rests.

**The handshake: every close pulls the resting target.** `_claim_side` (timed, asked-for, profit-action and watch-rule closes all use it) marks a working resting target `cancelled` with the claim's event and `resting` before anything is sent. `close_group` then runs `_cancel_pulled_target`, which cancels and reads the cancel back (`read_after_cancel`): `None` once it's gone, the close goes on sized to what's held; `_target_stands` when it still rests (the close never starts, the stop is watched again, you're told); `_target_took_it` when it filled first (recorded, `_end_the_watch`, nothing else sent); `_target_unclear` when it can't be read back (the target is `failed` with `TARGET_UNCLEAR`, the run is Needs you, the stop stays off and the alert says the group may have no stop and no target until you check). `held_back` treats a group whose latest target is held as `TARGET_UNCLEAR` as blocking any new close on that side. A close that ends without closing the group calls `_restore_target`, which for a resting target is `_put_resting_back` (still there: working again; filled: recorded; gone: placed again sized to what's held, or, when the broker doesn't show the group held, logged "not placed again" and alerted; with exits switched off meanwhile: cancelled, none placed). Both return words for the alerts ("armed again", "placed again at TastyTrade", "still resting at TastyTrade"; "" when none is back), and `_restore_target` refuses a side that is `busy` (another close is running on it). `_close_filled`, `_close_ended`, `_give_up`, `_refused`, `_cancelled` and `_recovered_close` go through `_target_then_stop`: the target first, then the stop, and the stop stays off while a target may still rest, as `_recover` does. `_recover` (a cut-off close, at startup) settles a pulled resting target first (`_pulled_target_filled`), and puts the stop back only once the target is accounted for.

**Live edits.** The run page's Change target takes 1–1000 on a trade that filled for a debit and 1–99 on a credit (`manage.target_range(entry)`; `TARGET_RANGE`, `DEBIT_TARGET_RANGE`).

### Paper trading (decision 0061)

A bot is **Live** or **Paper** (`bots.live`; there is no third mode). `bot_runs.paper` marks a pretend run, and `paper_fills` (`PaperFill`: run, `kind` of `entry`, `exit`, `expiry` or `action`, group, signed price per contract, contracts, reason, legs, time) holds what it did; migration 0037 adds both. An existing `live=False` bot simply reads as Paper. Old `status="preview"` runs are left alone and never show in the Paper trades view. Nothing in the paper path may reach a broker: the entry calls `orders.submit(..., preview_only=True)` and no paper module touches a broker client's send or place methods.

- **Modes.** A new bot is `live=True, enabled=False` (typed, cloned or imported; a clone then takes its source's mode in `bot_store.clone`). A change of broker or underlying, or one that makes `app_watched` true where it was false, sets `live=False, enabled=False`. `bot_store.set_mode(session_factory, bot_id, "live" | "paper", now, deps)` is the one way the route changes it (`POST /automation/<id>/live`); going Live first calls `bot_paper.end_paper`, which closes every open paper trade at the mid with reason `switched to Live` (the last price seen, marked "(last price)", when the stream has no fresh quote), and refuses to switch if any is left open (the route catches that `RuntimeError` or `ValueError` and flashes "Couldn't close the paper trades, so the bot stays in Paper."). Going Live also sets `enabled=False`, so an armed Paper bot is disarmed and arming it again goes through the confirm page (final review I1). Arming a Live bot always goes through `automation_live.html` (account, caps, where stops are held, and the tick box); the arm route checks both the hidden `confirmed=1` and the box (`understood=1`) server-side and sends anything less back to that page. A Paper bot has no confirm page (one with an app-watched stop still needs the tick box).
- **Entry** (`bot_entry._paper_entry`, `bot_paper.enter`). A scheduled Paper entry runs the same guards, filters, caps, strike pick and sizing as a Live one. Its single order check is `orders.submit(preview_only=True)`, so size limits, Freeze, No new trades and Stop all bots apply and a refused check is a `skipped` run. A passing check becomes a pretend fill: each leg at the mid the pick priced it at seconds earlier (the stream is not needed then: freshly picked strikes often have no stream quote yet, which skipped every such entry before 2026-10-16). A leg without one takes the stream's `(bid + ask) / 2`, waiting up to `STREAM_WAIT` (5 s, polled every `STREAM_POLL`) for a new strike's first quote; still none, or older than `QUIET_MAX`, skips the run with `NO_PRICE`. The combo is signed like a fill (a credit positive), written as `status="filled"`, `paper=True`, `live=False`, `fill_credit`, `filled_legs` and a `PaperFill(kind="entry")`. A Paper bot never chases and never rests a limit. It alerts "Paper: ... entered at ...". Never a broker's REST quotes beyond the entry's own chain.
- **Caps.** Paper follows the bot's own caps only. `orders.used_today` adds `bot_paper.used_today` (opening contracts of today's paper entries) for a Paper bot; `caps.paper_held` / `paper_closed` (via `bot_paper.closed_groups`) tell the open-trade count which groups a paper run's exits have closed, since it has no `BotExit` rows. A Live bot's counts never include paper runs.
- **Exits** are `bot_paper_exits.watch_pass` (next section). The live loops (`bot_loops`, `bot_settle`, `bot_timed`, `bot_integrity`, `bot_overnight`, `bot_rearm`) filter `BotRun.paper.is_(False)` so they never place, replace or reconcile anything for a paper run.
- **Freeze and paper exits.** Freeze stops the app sending orders. A paper exit sends none, so `watch_pass` does not read the Freeze switch (ruling for decision 0061; a live app-watched stop also ignores Freeze in the same way). Freeze does stop a paper *entry*, because the entry goes through the order check.
- **Reporting.** `paper_journal` and `core/paper_pl.py` (below) feed the Journal's Paper trades view (`/journal/paper`); `bot_stats.summaries` gives a Paper bot its paper totals in place of the journal's. A trade that closes exactly flat counts as closed but not as a win (`core.paper_pl`). Real journal code never reads `paper_fills`.
- **Run page.** A paper run's page has no "Manage this trade" controls, only a line saying there's nothing at the broker to close or change; a direct close POST is refused with "This is a paper trade, so there's nothing at the broker to close." (`bot_manage._nothing_to_close`).
- **Words.** The paper notice text is the same on the Journal's Paper trades view, the run page of a paper run (`automation_run.html`) and the page of a Paper bot (`automation_bot.html`): "Paper trades are pretend. Fills are estimated at the mid price, and stops are watched by the app instead of resting at the broker, so real results would differ." Alerts start "Paper:". The tag filter's state word is `Paper` (`definition.RESERVED_TAGS`).

### Paper exits (decision 0061, `bot_paper_exits.watch_pass`)

A Paper run gets no `BotExit` rows; `bot_paper_exits.watch_pass` runs in the 2-second bot-watch loop after the live watchers and records every exit as a `PaperFill` at the group's mid. It reads only `deps.hub`, the database and the pure `bots/` rules; it never calls the order path or a broker.

- **Stops and targets:** every one is watched by the app, even one the live path would rest at the broker. The levels come from `exit_plan.plan_group`, `stop_for` and `target_for`, as `place_protections` works them out. A stop on a short reads `watched_stops.evaluate`; a group stop reads `evaluate_group`. A target fires on the group's natural value at or under its close-at, as `bot_exits.watch_pass` arms one. Quotes count while under `QUIET_MAX` old and newer than the fill.
- **Watch rules, profit actions, timed close (with close DTE) and time actions:** the same pure rules as the live path (`watch.rules_for` and `evaluate` through `bot_watch._evaluate`, `watch.profit_outcome`, `timing.timed_close_due`, `timing.action_due`). A moved stop comes from `stops.profit_move` (profit actions) or `stops.action_move` (time actions), the helpers `bot_exits.profit_stop_calc` and `_moved_calc` also use. Where the live path checks a move against a resting order or the broker, paper checks it against the stream instead: the short's fresh ask, or the group's P&L at the mids (`bot_exits.level_problem`).
- **Confirming:** every trigger must hold `CONFIRM_PASSES` passes in a row (kept in memory, with the first pass's time); a watch rule confirms on `watch.confirmed`, as live, so a delta or S/L ratio rule also holds 30 s (#201). A close also needs a fresh, usable mid on every leg of the group; until then it waits.
- **Records:** an exit is `PaperFill(kind="exit")` with the group, its count and the price signed like a fill (a debit is negative). An exit or expiry counts in the group's **units**, as a live run's `bot_exits.group_units`: contracts x the gcd of the group's ratios (`caps.group_gcd`), priced per unit, so a partial close (`contracts_for`, `close_contracts` over `contracts x gcd`) closes what live would and price x count is still its dollars. The entry row stays per contract of the whole trade. A profit or time action also writes a `kind="action"` row with 0 contracts, holding its sig and any stop or target it moved, so it never runs twice and its new levels survive a restart.
- **Switches and caps:** a group's own stop-off or target-off switch (BotTradeOverride) is honoured: that level isn't watched. A watch rule that fires is written down (an "action" row with the rule's name), and groups it couldn't close yet (no mid) close on later passes without the rule being read again. `caps.paper_held` / `paper_closed` count a paper run's groups closed by its PaperFills, so a closed paper trade no longer counts toward the open-trade cap (`bot_paper.closed_groups` feeds `caps.RunRow.closed`).
- **Lapses:** a gap in passes longer than `LAPSE_AFTER` in the session sends one alert per bot and resets every count. Nothing is filled for the gap.
- **Expiry:** once the session has closed on a leg's expiration day, its group settles as `kind="expiry"` at intrinsic value, from the underlying's last price on the hub that day (a futures option: its contract's, read under "dx:" + its DXLink symbol from the nested chain, as the analyzer reads it). A later leg in the same group settles at its mid, if that quote is fresh. With no price from that day, the group stays open and this is alerted once.

### `bot_loops.py`
Four daemon threads started by `start(services)`, after it loads the stored market calendar (`economic_events.load_calendar`) (called from `__main__` and the launcher, like the alert checker); each `_loop` catches everything, logs it and carries on.
- **`bot-clock`**, every 10 s (slice 10: a floating bot goes to `_clock_floating` instead of its entry times: inside its window it starts `bot_entry.fire_floating` on a thread once per minute, remembered in `_floating_started` by New York day and minute; never `record_skip`): `clock_pass` first runs `_check_calendar` (once a day, if `core.sessions.calendar_covers(today)` is false, it alerts "Holiday calendar out of date": neither the fetched calendar nor the table covers the year; entries still run, as Tracker2's fallback does), then does nothing on non-trading days; `_day_lists` answers every list an armed bot relies on and alerts **once a day per list that can't tell**, naming the bots, once `economic_events.FIRST_CHECK_DONE` is set (the calendar loop's first check since startup has finished) (Tracker2 alerts this from its entry guards; here the clock covers specific-dates bots too); for each armed bot, a day outside `schedule.runs_on(bot, day, lists)` **creates no run at all**; otherwise `schedule.due` says what to do: fire (a thread running `bot_entry.fire`) or `record_skip` ("Missed its time"). The clock is the only scheduler.
- **`bot-watch`**, every 2 s (`_watch`): `bot_exits.watch_pass`, `bot_watched_stops.watch_pass` (slice 11), `bot_watch.watch_pass` (slice 7), then `bot_paper_exits.watch_pass`, each on its own.
- **Slow passes** (#204, Tracker2's `registry._log_slow_tick`): `_monitor` and `_watch` run their steps through `_run_steps(kind, steps, deps)`, which times each step on `_clock` (`time.monotonic`); a pass of `SLOW_PASS` (4 s) or more logs one WARNING, `bot watch pass took 4.2s: targets=0.2s, watched stops=0.1s, watch rules=3.6s, paper=0.3s` (a failing step is timed too).
- **`schwab-login`**, every 10 minutes (slice 11): `login_pass` → `schwab_login.check`.
- **`market-calendar`**, every 10 minutes: `economic_events.refresh_if_due` (network calls happen only here and on Refresh now).
- **`bot-monitor`**, every 30 s: `reconcile`, `bot_limit.check_pass` (slice 17: the resting entries, at every hour), `check_exits`, `bot_exits.monitor_pass`, `bot_manage.recover`, then `bot_timed.timed_pass`, `bot_timed.actions_pass` and last `bot_integrity.check`, each on its own (one failing never skips the rest).
- **`bot-audit`**, every 60 s: `bot_audit.audit_pass`. Every loop's body runs through `_pass`, which logs a failure and records a good pass for the schedule check. Before the loops start, `recover` runs `reconcile`, `check_exits`, `bot_exits.recover_targets`, `bot_manage.recover` and `bot_watched_stops.recover` once (each step on its own; one failing never stops the others).
- **`check_exits`:** today's `filled`/`partial` runs (not in `ACTIVE`) with **no exit rows** (and a bot that has a stop or target), or with rows still `placing` after 2 minutes: alert once "Needs you: exits may be missing — check your broker", and mark those rows `failed` (a resting target's with `TARGET_UNCLEAR`, and the alert says a profit target may rest). It **never re-places**: a `placing` row may have a live stop the app doesn't know about.
- **`ACTIVE`** (in `bot_entry`) is the set of run ids with a live thread, from the claim to the settle: **the root's id and every child's id**, the child added as it is created and all removed when the entry thread ends, so recovery leaves a tranche alone while the chase is working. `reconcile` skips them. `reconcile` **does nothing while Freeze is on** (a fill it found then couldn't get its stops). For each other `running` run, `_settle` **re-reads the run's status first** (the entry thread may have settled it), then: a stale run (more than 5 days) or an **orphaned** one (its bot was deleted) alerts once and is left alone (its reason is rewritten to start with "Needs you", and marked runs aren't alerted again). It calls `orders.resolve_unclear` and **waits while any of the run's order-log rows is still unclear**, or while `orders.unclear_symbols` covers the run's legs: a replace that timed out may be working under an id the app doesn't have. A run with no order id then looks for one in the order log. Otherwise it reads the order (in the run's account), cancels it if it is still working (never chasing it; **at most `MAX_CANCELS` = 2 cancels of that order in all**, the chase's own included, then "Needs you" once instead of cancelling every pass), and records a fill and hands it to the exits (`hand_to_exits`: an exception keeps the fill and alerts), or marks the run `missed`.

## Manual bots: attaching rules to a trade
A manual bot (`manual_bots`, `bots/manual.py`'s `ManualRules`, #158) is a template. **`services/manual_attach.py`** turns it into a hidden **per-trade bot** for one open trade and hands the trade over as a bot hand-over does (`bot_adopt`):
- `read_trade(deps, key)` → `(Trade, problem)`: the journal trade (a split half stands for its whole trade) built from its **open** legs (`remaining`), each priced at its opening fill (`bot_adopt._fill_price`). Refused: no such trade, closed, a non-option leg, legs on more than one underlying ("Manage this trade works on one underlying."), not TastyTrade/Schwab, no broker order id, and a trade a bot's run already carries ("This trade is already managed by a bot."). Unlike a hand-over, any open trade qualifies: opened any day, partly closed. Futures go through `bot_adopt._futures_trade` (TastyTrade's series).
- `matched(trade, today)`: the run's legs in one group 0; units are the gcd of the open quantities, so a 4-lot condor with 1 closed is a 3-unit run whose `fill_credit` is the net opening credit per unit of the open legs.
- `bot_for(rules, trade, manual_bot_id)`: `BotDef(per_trade=True, live=True, enabled=False)` with one group, **Whole trade**: the stop as % of the entry lost (`stop_basis "group_entry"`) or $ per contract, the target as a group's (% of the credit kept, or $), `close_time`/`close_dte`, the rules' alerts as default alerts, the default exit chase (`ignore_bidless_longs` off). Its legs are a shape only (`pick` premium, `dte` clamped to 0–60); `per_trade` skips validation's entry-time rule. Futures: profit target only (no stop, exit time or alerts); no target is refused.
- `attach(deps, key, rules, manual_bot_id)` → `bot_adopt.Outcome`, under `bot_adopt._LOCK`, never raises: saves the bot through `bot_store.save` and marks it `hidden` with its `manual_bot_id` (its journal tag: the trade's own first tag by name, else a "Manual" tag made if missing), records the run with `bot_adopt.record_run` and calls `bot_entry.hand_to_exits(live_check=True)`. The switches are not checked first: every exit goes through `orders.submit`, so Freeze (which replaced Stop all bots) refuses the sends there while the run stands.
- `nearest_expiry(trade)`; `assignable(trade)`: the first leg's underlying that settles in shares (`underlyings.get`), else None. The timed close already counts from each group's nearest expiration (`bot_timed.group_expirations`).
- Hidden bots never show in `listing`, `armed`, `archived_count` or the ticket's bot picker. `bot_store.label(bot_id)` is the name a bot's runs show under: a per-trade bot's manual bot's current name; the runs and run pages use it.

## Counting against the daily limit
The order path (`services/orders.py`) is where the per-day contract limit lives, and a tranche must not count twice.
- `used_today` sums today's opening `send` rows for the bot. It **leaves out sends under a child run** (an outer join to `BotRun` with `parent_run_id IS NULL`), so a tranche's fresh order for the rest isn't added to the first send, which counted the whole entry.
- `_bot_facts` knows a request is a tranche when its run has a `parent_run_id`. For an opening send that is a replace or a tranche, it subtracts the request's quantity from `used`, so the check sees the entry's quantity once. For closing orders of one of the bot's own runs, `live` comes from the run (the exits follow the run).
- Max entries per day counts distinct roots, not tranches, and never a Preview order run, a trade handed to the bot (`adopt-…`, slice 12) or an entry from the Trade page (`ticket-…`, slice 15). Max open trades comes from `bot_entry._open_trades`, which reads the bot's `filled` and `partial` runs and their `bot_exits` rows and hands them to the pure `bots/caps.open_trades` (Tracker2's `guards.under_position_cap`, which counts the `BotPosition` rows it writes at fill). It never reads the journal: the journal only changes on a sync, so an unattended bot's same-day trades would never count. Any failure raises, and the guard turns that into a skip.

## The journal link
`services/journal.py` has `bot_links(session_factory)`: a map from the opening order id (`{broker}:{account}:{broker_order_id}` from `bot_runs.broker_order_id`) to the run and its bot, built on read the same way trade edits are. A position whose opening order is in the map belongs to that run. It carries the bot's **tag** (`bots.tag_id`) as well as its own, added as the journal is built the way Stocks is (decision 0072); a trade matched to a bot (`journal.matched_links`) carries it too. Its **split** default comes from the bot: the iron condor is built as two sides when `split_iron_condors` is on, unless the trade's edit says combined. `trade_edits.split` is nullable: `None` is no choice, `True` split, `False` an explicit **Combine**, which wins over the bot. The journal shows a `bot · name` badge linking to the runs. (Tracker2 does this with `attribution.link_bot_positions`, because it stores positions as rows.)

### The Paper trades view (decision 0061, `services/paper_journal.py`)

`paper_journal.trades(session_factory, start, end, bot_id, tag=)` lists runs with `paper=True` and an entry `PaperFill` (old `status="preview"` runs have neither, so they never show), newest first, as `PaperTrade`s; `totals(trades)` gives P/L, wins, losses and win rate of the closed ones. A trade is closed when `caps.paper_held` says every group is gone; the "action" rows are ignored. The arithmetic is the pure `core/paper_pl.py`: P/L = (entry price x contracts + sum of exit price x exit contracts) x `BotRun.multiplier`, all prices signed like a fill (a group close prices only its group, a whole-trade close the whole trade, so the exits just add). With `split=True` (the page passes it; `bot_stats` doesn't, so a bot's counts stay per trade), a run of a bot with `split_iron_condors` whose legs `paper_pl.condor_sides` reads as an iron condor (no group holding both rights) becomes two `PaperTrade`s with `side` "put" and "call" (#181): each side's entry price is `paper_pl.legs_price` of its legs' mids on the entry fill, and it takes only its own groups' fills. A run with a whole-trade (group None) close, or an entry without its legs' mids, stays whole. "Closed by" is `paper_pl.closed_by`: the exits' reasons, each once, or the last expiry's when nothing exited it, so a stopped side whose wing expires at the close says "stop". `tag` (#219) keeps the bots whose filing tag's name or one of whose `Bot.tags` labels matches, ignoring case (`_bot_tags`); `paper_journal.tags(session_factory)` lists those names over the bots with paper runs, for the page's tag picker. The page is `/journal/paper` (`journal.paper_page`, `journal_paper.html`). `paper_journal.fills(session_factory, run_id)` (#182) lists a paper run's entry, exit and expiry `PaperFill`s leg by leg as `LegFill`s from each row's `legs` (a leg's `mid`, or an expiry's `value`), with the leg's count (a group fill's units x ratio / the group's gcd) and dollars signed as money in; the run page shows them as its Fills table (`run_context`'s `paper_fills`). Live (#183): a `PaperTrade` is closed once every group holding a sold leg is (any group when none does), at that group's last close; a bought wing still held is worth 0 (`wing_held`, its legs in `held`). `paper_journal.live_pl(trades, hub)` prices each open one with `paper_pl.marked_pl` (its `exits` so far plus its `held` legs at the quote hub's marks; None while one has no mark), keyed by `PaperTrade.key` (`run_id:side`, or `:all`). `/api/paper-open-pl` (`journal.paper_open_pl`, the page's filters) returns it in `/api/open-pl`'s shape, so the page reuses `open_pl.js`. `web/live.watch_paper` pushes `paper_journal_changed` after each commit that saved a `PaperFill`; the page names that event with `data-live-event` and reuses `journal_live.js`. `bot_stats.summaries` returns `Stats.paper` (the same totals) for a bot with `live=False`, in place of the journal's numbers; the Automation list tags them "paper". Nothing here touches `journal.load_journal`, so the real journal never sees a paper fill.

## Preview order
`bot_entry.preview_order(deps, bot_id)` replaces the bot page's old Preview now button (`POST /automation/<id>/preview`, `automation.preview_now`, template `automation_preview_order.html`). It claims no run and saves none. It runs `_guard(manual=True, require_open=False)` (archived, Freeze; not the regular session or the cut-off, as Tracker2's `check_manual(require_open=False)`, since it never sends), picks through `_find_legs` (shared with `_fire`: expirations, chains, spot, `_pick`), prices through `_opening_price` (shared with `enter_picked`), sizes a dollars bot with `_size_by_buying_power`, then calls `orders.submit(preview_only=True)`. It returns a `PreviewResult(ok, reason, legs, price, buying_power, graph, contracts, exits)`. `exits` is one line per group from `exit_plan.group_lines` (the same words as `exit_plan.preview`, at the mids and the order's price; empty if they can't be worded), shown as the page's Exits row. `graph` is the picked legs as a `Position` of `PositionLeg`s at the mids, run through `core.risk_graph.graph_legs`; the page draws it with `_risk_graph_panel.html` and `static/js/preview_order_graph.js` (`_mountRiskGraphGroup`). `buying_power` is read from the TastyTrade preview's message and is None for Schwab. The order path still logs the check as a `preview` row in the order log. `fire(manual=True)` and the old `status="preview"` runs remain for existing tests and history; the Trade-page futures ticket (`bot_limit.place`) on a Paper bot still ends as a `preview` with no pretend fill.
